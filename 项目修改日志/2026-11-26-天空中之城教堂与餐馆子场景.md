# 天空中之城教堂与餐馆子场景

日期为 2026-11-26，任务编号为 `SKY-PUBLIC-INTERIORS-20261126`。本次由 Codex 完成开发与验收。批准写入后，记录子 Agent 负责同步本次两段中英文协作记录。

## 玩家进出建筑

在天空中之城的西北晨钟教堂门廊或南侧金穗餐馆门廊，走进传送阵就会进入对应室内。两间室内都是同一区服共享的公开地图，各有一条公共线路。回到室内门口即可回街上，出生在刚离开的建筑前。角色在室内下线后，重新选角会从最近确认的室内门口进入。

| 建筑 | 室内地图编号 | 天空城上的门心（X / Y / Z，米） | 回到天空城的位置（米） | 一区常驻宿主 |
| --- | ---: | --- | --- | --- |
| 晨钟教堂 | 41 | −330 / 0.08 / 270 | −330 / 0.12 / 264 | GS1 |
| 金穗餐馆 | 60 | −42 / 0.13 / −196 | −42 / 0.14 / −190 | GS2 |

沿用主城和天空城之间的零号门。天空城一侧的传送阵横移 6 米到路边，保留原返回出生点。实际导航显示，旧阵心恰在出生点通往教堂的街道中心，走向教堂会先传回主城。建筑门口取自当前扩建后的街区。公共地图、门号、坐标及两端落点统一维护在 `LYF_Server/区服部署/配置/公共地图传送.xml`。更改该文件后要重新编译 Network 并同步两端 DLL。区服文件分别决定室内所属 GS 和线路。

## 美术、角色尺度和烘焙

教堂采用本机 RO 参考工程 `sc_zzms_001` 的彩窗、祭台与长椅，餐馆采用 `sc_ysld_jiuba_001` 的餐桌、吧台及舞台。静态网格、手绘材质和烘焙纹理已转换为本工程原生资产，场景使用现有角色、相机和地图管理组件。合并后的教堂建筑有 17 个渲染批次，餐馆有 21 个。

- 教堂建筑和家具按 RO 原始尺寸的 90% 制作，餐馆为 88%。用原尺寸的剑侠和魔剑士角色测得可见高度分别为 1.982 米和 2.184 米。教堂长椅座面约 0.56 米，餐椅座面约 0.60 米，餐桌台面约 0.92 米。
- 保留原场景烘焙的线性 RGB 光照图和第二套 UV，重新烘焙本工程角色使用的照明探针与环境反射。教堂 378 个角色光探针，餐馆 141 个。两间室内的场景灯均为 Baked。走廊、家具碰撞、小地图和客户端与服务端的寻路数据随尺度同步生成。
- 场景与角色对照图为 `_temp/sky-city-interiors-20261126/晨钟教堂-角色实拍.jpg` 和 `_temp/sky-city-interiors-20261126/金穗餐馆-角色实拍.jpg`，另有各自的入门视角。

## 运行验收

- 从分支基线加本次业务改动的隔离副本编译六个服务端工程，工作区客户端 LYF_Game 编译通过。干净客户端在改动前后均有同一处既有 `MainCtrl.cs` 找不到 `CurrencyExchangeCtrl` 的 CS0246。
- 本机隔离一区启动两个 GS，使用独立 MySQL 测试库。两个实际 TCP 游戏会话分别进入不同室内，并在同一条餐馆线路共处。餐馆下线重登恢复地图 60，离开又能回到餐馆前。人在餐馆门前不能用教堂门号进教堂；原双城零号门仍能往返。
- 一个使用正式魔剑士模型的隔离 Unity Play Mode 客户端，经 TCP、KCP、正式 YooAsset 场景加载及真实门触发完成四次过门。路线依次是天空城、教堂、天空城、餐馆、天空城。每次都核对了位置、同一角色模型实例和游戏服回执。
- 两种正式体型沿各室入口和主通道抽样检验碰撞净空，记录中未碰到家具或墙面。两份 Windows x64 场景资源包在 StrictMode 下构建并实际重开。二区仅登记配置，未启动二区，未做双 Unity 客户端同屏、完整独立 Player、手机真机或 GPU 性能测试。
- 制作时曾发现默认光图解码使参考场景过暗，改为使用 RO 的原始 RGB 烘焙数据。联网实测另复现了门心放在旧城区坐标、旧地图位置覆盖新落点、餐馆重登回到默认城等问题。网络时间线与设计取舍见 `项目分析/项目难点.md` 本任务编号。
