# 副本逐首领难度掉落

## 需求与配置

本次编号为 `DUNGEON-BOSS-DROPS-20261127`。击败一只正式战斗首领时，同地图、同实例的在场队员各自记录击杀，首次符合本周期资格的角色直接收到背包掉落。每个副本、难度和首领组合有独立记录。角色在同周期换队、换实例或重新登录，保留已经击杀的首领及掉落状态。

| 难度 | 各首领刷新 | 单次掉落的魔物硬币（503） |
| --- | --- | ---: |
| 新秀 | 每日北京时间 08:00 | 1 |
| 初心 | 每周日北京时间 08:00 | 2 |
| 奇险 | 每周日北京时间 08:00 | 3 |
| 临危 | 每周日北京时间 08:00 | 4 |
| 旷世 | 每周日北京时间 08:00 | 5 |
| 终绝 | 每周日北京时间 08:00，各层共用同一难度资格 | 6 |

道具和数量为本次可调整的初始值。两张工作簿可从 Unity 的「工具 → 副本 → RO场景编辑器 → 全局配置 → 首领难度奖励表 / 首领奖励包表」打开。前者的永久 `Id` 关联角色进度，`DungeonId`、`DifficultyId`、`BossId` 定位本次击杀，`PackId` 引用后者的 `Id`。`ItemId` 和 `ItemCount` 决定一次实际入包的单种物品及数量。已投用的奖励行请保留原 `Id`，调整物品或改包号都可继续沿用原进度。修改源表后从项目根运行：

```powershell
.\Luaban\MiniTemplate\gen_dungeon_difficulties.ps1 -BossAwards
```

当前对应北方异变之森 4050 的 9751、北方异变之森试炼 4051 的 9801，以及达纳托斯之战 4060 的 5501 憎恨、5502 绝望、5503 悲哀。按官方怪物目录的首领标记与实际波次模板交叉核对，三张登记共 5 个绑定、30 行难度配置。4060 的流程终结器 5357 不在奖励表中。4050、4051 的客户端场景登记在本次工作时 `sceneLocation` 均为空。

## 实现与验证

- 服务端 `SceneWaveSpawner.CountDeath` 在实际死亡时结算，沿用 `Players` 的角色、地图、实例筛选。个人击杀和已入包周期分别由 `DungeonBossKill`、`DungeonBossDrop` 保存到原角色次数表。周期采用现有 UTC 日界与周日周界。背包和次数进入同一份角色版本存档及中心服事务。空间不足时仍记录击杀，玩家腾出空间后在本周期再次击败同一首领可获得掉落。
- `DungeonBossProgressNtf` 单播个人进度和这次实际入包的内容。原背包增量负责同步物品，现有系统提示展示名称和数量，副本任务追踪显示已击杀/总数，任务详情列出已击败的首领。入场时按本人的存档重新计算进度。
- 已通过 Luban 导出与 30 行配置引用校验，服务端解决方案、Unity 游戏与编辑器程序集和 Windows Player 热更程序集编译。待提交的独立源码也完成了 Network、GameServer、GateServer 及 Windows Player 编译。
- 游戏进程回环测试通过 15 项，覆盖达纳托斯三只真实波次首领、成员资格不同、同地图不同实例、重复击杀、角色存档往返与重进、日/周和跨年边界、终绝跨层、满包记录与再次击杀。首个隔离测试输出目录混入了依赖项目的旧版 .NET 类库，按 GameServer.csproj 的正式依赖重建测试运行目录后通过。独立构建快照补齐了共享嵌入传送配置及任务版工程文件后通过。
- 原始证据在 `_temp/boss-drops-20261127/` 中。`build.log`、`smoke.log`、`config-check.txt`、`LYF_Game.compile.log`、`RO.SceneEditor.Editor.compile.log`、`working-player.log` 记录各项检查。尚未用 Unity 账号在画面中手动击杀，尚未连正式数据库做下线重登验收。
- 实现、表格与验收由 Codex 直接完成。经开发者批准写日志后，Codex 原生子 Agent 仅同步两段中文并核对增量，一轮通过。额度采样使用 `token-monitor` 的 `collect`、`report` 和当前会话原始日志。可核对 `collect.txt`、`report.json`、`task-usage.json`、`context-compactions.json`。截至北京时间 21:44，主任务约 1,215 万含缓存 token，中文校对单轮约 45 万。当前会话累计压缩 1 次。
