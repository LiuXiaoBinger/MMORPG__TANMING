# 同一区服多 GameServer 与公共地图分线

编号 `REALM-GS-LINES-20261125`。功能分支 `codex/feature-development`。Codex 直接实现，中文协作记录按本次新增段落同步。

## 实现和参考

选服页继续选择逻辑区服。ControlServer 保存 GS 登记、场景实例及角色名额，GateServer 维持连接，GameServer 执行游戏，MasterServer 处理区内社交与进本集结，CenterServer 按账号和区服读取角色并确认存档。默认 XML 为两台 GS，地图 0 和 1 各有两条常驻线，每线 500 人，全部达到 400 人后按需扩线，最多八条。参数来自本项目示例。部署步骤与字段见 `项目分析/同区多GS与地图分线.md`。

参考 RO 的 `controlserver/process.cpp`、`controlserver/scene/gsmanager.cpp`、`controlserver/scene/scenemanager.cpp` 和 `controlserver/protocol/scene/rpcc2n_changesceneline.cpp`。该进程还初始化账号会话、登录控制、排队、踢号与白名单；本次实现选取同区分线、GS 登记和角色交接所需职责。实际难点见 `项目分析/项目难点.md` 同编号。

## 验收

- 分别构建工作区服务端与功能分支干净投影，并按每个服务自己的输出目录启动。修正 Windows PowerShell 中文脚本编码、Control 和 Master 缺少的协议运行库后，通过 `Start-Realm.ps1` 启动两个 GS、一个 Control、一个 Master、一个 Gate，对接真实 Center 与独立 MySQL。通过 12 组网络场景检查，见 `_temp/realm-lines-20261125/verified-deploy.txt`。测试角色与库均独立于原游戏数据。
- 三个 TCP 客户端进入同一逻辑区，第一线满员进入第二线。同机不同场景 UID、跨机进程切线、两侧出现与离场、满线拒绝、同区聊天和组队、全队同一副本、退出后释放名额均通过。扩容到 82 格的背包在迁移时已入库。测试将各线容量降到 2，增加角色后实际开出并进入第 4 线，退出后回收到三条常驻线。以上 GameServer 进程运行在同一台机器。
- 工作区客户端编译通过。隔离 Unity Editor 加载取自正式预制体的小地图，核验初始隐藏、模板与文本引用、动态人口和当前线、选择事件及副本隐藏，证据在 `_temp/realm-lines-20261125/ui.log`。干净功能分支客户端的三个错误均位于 `QuickTaskPanelWidget.cs`，与未改动基线的三个诊断一致，见 `_temp/realm-lines-20261125/branch-check.json`。
- 验收从选服后的网关开始。尚未验证正式账号全程登录、Unity Player、真机、KCP 实时移动、多机容灾和生产负载。运行时线路目录在控制服内存中。未部署到线上。
- 额度原始统计保存在 `_temp/realm-lines-20261125/collect.txt`、`report.json`、`context-compactions.json` 与 `token-summary.json`；可见文本类别为估算，账户剩余额度本地不可测。
