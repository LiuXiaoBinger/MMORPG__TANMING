# 底部血条与蓝条加宽加粗

- 日期：2026-11-16
- 分支：`codex/feature-development`
- 提交：`1f11505`（预制体改动；日志与协作记录另起一次提交）
- 目标：底部技能栏左右两侧的血条（红）与蓝条（蓝）太细，用户要求「加宽加粗」。

## 一、需求与落地

| 用户要求 | 落地方式 |
| --- | --- |
| 血条/蓝条太细，加粗 | 高度 10 → **20**（翻倍） |
| 加宽 | 宽度 340 → **400**（+60，约 +18%） |
| 不要挡住技能槽 | 中心 y 由 −61 下移 5px 到 −66，条的**顶边位置保持不变**，加粗部分向下长 |

定位结论（编辑器态核实）：

- 血条 = `UIRoot.prefab` 的 `Canvas/MainView/RoleCurrtInfoWindow/Slider_hp`，蓝条 = 同级的 `Slider_mp`；两者都是 Unity `Slider`。
- `RoleCurrtInfoWindow` 尺寸 930×150、锚点 (0.5,0)，`anchoredPosition=(0,100)`，是底部技能栏（Q/E/1/2/…/F + 中央 R 圆盘）的容器。
- 每个 Slider 下只有两个子节点：`Fill Area`（锚点 0~1 拉伸，sizeDelta −15/−1）→ `Fill`，以及铺满的 `Background`。两者都是拉伸锚点，父级尺寸变化时自动跟随，不需要单独改。
- 贴图 = 图集 `LYF_MMO/Assets/artres/Resources/UI/Atlas/Common1.png` 里的 `UI_Common_Bg_Normal_04.png`：28×28 圆角框，九宫格边 11/13/12/10，`Image.type = Sliced`。填充色红 `(0.98,0.39,0.48)`、蓝 `(0.25,0.65,1)`，底槽深蓝 `(0.12,0.23,0.34)` alpha 0.9。

## 四、设计取舍

1. **「细」的根因是贴图被压扁，不是颜色问题**：`UI_Common_Bg_Normal_04` 是 28×28 的圆角框，九宫格上下边合计 23px。放在 10px 高的矩形里，九宫格被强行压缩到 0.43 倍，看起来就是一根线；抬到 20px 后压缩比降到 0.87，槽体与填充的层次才显出来。所以只调 RectTransform 就能解决，不需要换贴图或改颜色。
2. **只下移 5px 而不是整体上移**：高度翻倍若保持中心不动，条的上下各长 5px，上边缘会顶进技能槽底板。改为中心下移 5px，让**顶边固定、向下生长**，既加粗又不侵占上方布局。
3. **宽度取 400 而不是铺满底板**：底板横向 463~1421，中央 R 圆盘占 897~1023。血条右边缘 890、蓝条左边缘 1030，与圆盘各留 7px，视觉上仍属于各自一侧、不贴住圆盘；外侧则比原来多伸 20~23px，整条更饱满。
4. **不改子节点**：`Fill Area` 与 `Background` 都是 0~1 拉伸锚点，父级 `sizeDelta` 变化会自动重算，单独去改反而会破坏比例。

## 五、验证结果（Unity 2023.2.20f1c1，主城 Play 实例）

- **改前/改后实机对比**：在运行中的 `Scene_MainCity` 实例上先截改前图，再把 `Slider_hp`/`Slider_mp` 设为新值截改后图；对比图 `_temp/hpbar-20261116/bar_ab.png`（上=改前 340×10，下=改后 400×20）。改后条体明显变粗，红/蓝填充与深蓝底槽层次清楚，左右端为圆角，未压到技能槽、未被屏幕裁切。
- 把同样数值写回预制体后 `AssetDatabase.Refresh()` 读回：`Slider_hp (−270,−66) 400×20`、`Slider_mp (270,−66) 400×20`，与预期一致。
- 控制台 0 错误。

## 六、未验证与遗留

- **未验证战斗中的实时表现**：截图只覆盖静态画面（当时血量约 96%，能看到填充右端留出的深色余量）。掉血/回蓝时的填充跟随、低血量与空条观感、以及 `Slider` 的过渡是否顺滑都未实测。
