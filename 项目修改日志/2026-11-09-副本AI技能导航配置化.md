服务端由共享场景登记的 `battleConfig` 选择战斗配置，实例持有所属目录与导航，去除 `4060` AI 门禁；客户端由 `battleResourceRoot` 选择表现目录，播放器绑定所属场景。四项效果路径、采集标题和不淡出尸体 ID 都已配置化。35 个业务/配置/测试文件已提交为 `6a094fb96508f975c494a5bdf51a4a0898bc41f4`，并推送至 `codex/feature-development`。没有部署或重启正在运行的本机服务器。

## 设计与配置使用

1. 在共用 `LYF_MMO/Assets/GM_Game/Resources/Dungeons/Scenes/{SceneID}.json` 登记场景流程/实体资源与 `battleConfig`。服务端按 SceneID 读取嵌入的同一登记；空 `battleConfig` 保留原通用场景流程，不借用魔神塔战斗资源。
2. 有战斗资源的场景让 `battleConfig` 指向正式发布目录内的配置。`SkillDirectory` 提供 `Tables.xml`、`SkillData`、`Lua`、`Curve`；`NavigationPath` 指定本地图导航，`TreeDirectory` 指定主树及引用树。`SceneTree` 可空，空时沿用场景 XML 事件规则。
3. 需要 NPC 映射时登记 `Npc npcId/entityId`；需要时间轴时登记 `Timeline entityId/script/codeProfile`。Lua 通过绑定选择脚本及同名全局表；Code 仅支持原 `DaNaTuoSi`、`BossController` 两个显式实现。无 Timeline 时可以不填 `LuaDirectory`/`TimeAxesPath`；有时间轴时按实际执行模式提供对应文件。新增行为树节点、Lua API 或 Code 行为仍需要真实实现，配置本身不会生成这些能力。
4. 客户端 `battleResourceRoot` 下提供现有格式的 `MonsterSkills`、`MonsterBuffs`、`MonsterNotices`。三个目录缓存以根路径为键，播放对象持有所属目录；空根不加载魔神塔目录，也不增加缓存项。`hitWordResource`、`portalResource`、`airWallResource`、`collectionResource` 指定四项表现路径，`collectionTitle` 指定交互标题；`MonsterBuffs.json` 的 `NoFadeEntityIds` 指定保留尸体的实体号。
5. 按既有嵌入/发布机制包含新场景波次、实体、导航、表、树、脚本和客户端资源。场景登记嵌入不等于其他依赖已自动部署。正式发布后新建副本实例使用所选配置；本次没有执行运行服务器切换。

魔神塔 4060 仍使用原资源目录与数据、公共 `MMonsterAnimator`、原 Lua/Code 调度和已有两种 Code 实现；采集标题仍为“破坏魔法阵”，不淡出列表仍为 5357/5501/5502/5503。4050/4051 的战斗/效果配置明确为空，标题为“采集”。删除的 `Moshenta.Waves.xml`、`Moshenta.Creatures.json` 是重复嵌入别名，不是删除实际 XML/实体资源文件。
