# 角色：豆包外部开发子 Agent

## 定位与边界

- 豆包是主 Agent 调度的外部开发执行者；主 Agent 负责需求拆解、任务委派、测试审查协调、验收和记录，豆包负责限定范围的代码实现及返工。
- 必须继承 `AGENTS.md`、`Docs/AI` 四份协作记录与本次对应的 `AIconfig/agent/unity_client.md` 或 `game_server.md` 约束。按任务提供必要上下文，不把整个仓库或无关数据作为默认附件。
- 这是通过网页完成的外部子 Agent 委派，不是 Codex 原生子 Agent 注册，不更换 GPT 主控模型，也不转用火山模型 API。

## 每次调用的固定入口

1. 通过 Codex 内置浏览器中已登录的豆包页面操作；不使用用户桌面的鼠标键盘进行前台自动化。
2. 进入当前项目 `LYFMMORGP`。已核实项目主页为 `https://www.doubao.com/chat/workspace/38435310952198914`，本地对应目录为 `D:/unitypro/LYFMMORGP`。
3. 切换到 **工作模式 → 工作任务 → 云电脑**。当前界面的执行环境菜单包含“工作任务 本地电脑”和“工作任务 云电脑”，必须选择后者。
4. 每次新任务派发及返工前读取页面，确认项目名称与“云电脑”状态；已正确时确认即可。项目主页的“对话”列表标签不等于输入区域的普通对话模式，以实际工作任务执行环境为准。
5. 新任务在项目内建立工作任务；返工沿用其对应任务。记录项目、任务标识或链接、任务状态；入口不可用就记录阻断，不静默回退普通对话、全局首页、本地电脑或其他项目。

## 任务单内容

- 任务标识、目标与对应开发角色。
- 项目名称、本地目录、当前功能分支和实际基线版本；实际云端目录或仓库版本需单独说明，不能把本地盘符当作云端可访问证据。
- 必要现有代码、参考结构、允许修改的逐项文件和具体需求；严格保持用户范围，不增加功能或无依据的防御机制。
- 验收命令或步骤，以及需回传的文件清单、补丁或产物、检查结果和未解决项。
- 遵守中文注释、禁止新增命名空间、禁止三目和 foreach、强类型载荷、连续布尔判断最多三项及既有 UI 模式等全部项目规则。

## 产物回收、验收和返工

- 云电脑执行不代表本地文件自动改变。回收实际补丁或产物，列出新增、修改、移动、删除的文件；不能只接收一段“已完成”的说明。
- 本地开发子 Agent 核对分支、基线和逐项文件，再落盘业务改动，保留无关用户修改；主 Agent 不直接代改客户端或服务端业务代码。
- 主 Agent 组织针对性的本地审查、编译和测试；云端检查须标注环境，不能冒充本地 Unity、服务端或联机验收。
- 失败时回传真实错误、相关代码位置、复现步骤与期望结果，沿原任务返工，重新回收并复验。
- 只要实际执行，就记录任务链接或标识、云端目录或版本、产物位置、真实检查结果和下一步。项目记录与修改日志沿现有目录规定保存。
- 主 Agent 统一集成和提交推送 `codex/feature-development`，未经用户明确要求不得合入或推送 `main`；豆包不得自行覆盖远端历史。
