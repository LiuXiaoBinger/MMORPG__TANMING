# LYFMMORGP 项目协作流程与分工边界

本文件是 AIconfig 内部的角色协作准绳，主 agent 依据此文件调度子 agent。
所有角色执行任务前必须先读本文件，确认自己的职责与流程位置。

## 角色清单（对应 agent/ 下定义文件）
| 角色 | 定义文件 | 一句话定位 |
|---|---|---|
| 产品经理 | agent/product_manager.md | 需求、范围和验收标准 |
| 策划与系统架构师 | agent/architect.md | 玩法、数据和协议设计，不写业务码 |
| Unity 客户端工程师 | agent/unity_client.md | 客户端实现 |
| 游戏服务端工程师 | agent/game_server.md | 服务端实现 |
| 测试工程师 | agent/tester.md | 编译、联调、回归和问题复现 |
| 代码审查员 | agent/code_reviewer.md | 质检，不改码 |

## 标准执行流程
1. **需求拆解**：产品经理明确目标、范围、验收标准和优先级
2. **方案设计**：策划与系统架构师输出设计、数据表、协议清单和任务拆分
3. **并行开发**：客户端与服务端按边界实现；协议变更先更新 `LYF_Server/ProtoBuf/proto`
4. **测试验证**：测试工程师执行编译、静态检查、专用测试和联调，结果写入 `Docs/AI/TEST_REPORT.md`
5. **代码审查**：代码审查员按 quality_gates 输出问题清单和结论
6. **打回修复**：问题打回对应开发角色；审查员不直接修改业务代码
7. **复审与集成**：测试复验，主 agent 进行最终集成验证并更新交接文档

## 分工边界（谁干什么）
| 工作 | 负责角色 |
|---|---|
| 需求与验收标准 | 产品经理 |
| 玩法、数据表和协议设计 | 策划与系统架构师（协议先改 `LYF_Server/ProtoBuf/proto`） |
| 客户端实现 | 客户端工程师 |
| 服务端实现 | 服务端工程师 |
| 编译、联调、回归测试 | 测试工程师 |
| 代码质检 / 打回 | 审查员 |
| 需求澄清 | 主 agent -> 产品经理 / 策划架构师 |
| 集成验证 / 最终合入 | 主 agent |

## 规则
- **参考移植优先照原代码**：用户指定参考项目时，沿用其代码结构、接口、职责和调用时序，仅做当前工程必要的最小接入适配；不得自行扩展功能、通用管理层或防御包装。额外功能由用户明确提出后再实现。
- **按真实需求审查**：先审核参考一致性和简洁性，不为无生产依据的假设重入/极端测试增加快照、代次包装、等待确认、重试或额外状态；已复现的实际问题只作有依据的最小修正。
- **一类一文件**：每个顶级类、接口、枚举和委托必须独立放置在一个同名源文件中；禁止通过聚合文件定义多个业务类型。
- **主 Agent 边界**：主 Agent 只负责需求拆解、协调产品/策划、委派开发、组织测试审查、验收和更新记录，不直接修改客户端或服务端业务代码。
- **代码委派**：涉及业务源代码的新增、删除、重构和修复，必须交由对应客户端或服务端开发 Agent 执行；主 Agent 只能修改协作配置和记录文档。
- **强制创建子 Agent**：凡涉及客户端或服务端业务代码，主 Agent 必须先创建并委派对应开发子 Agent；不得以主 Agent 临时代改、直接补丁或自行提交替代委派流程。
- 谁的问题谁修，审查员不代改
- 协议变更必须先改 `LYF_Server/ProtoBuf/proto` 再生成代码和进入开发，禁止先写业务代码后补协议
- 每个任务默认最多 3 轮审查；超出由主 agent 决策
- 代码审查通过前，禁止声明"完成"
- 每项工作开始前读取 `AGENTS.md` 和 `Docs/AI` 四份记录；结束后更新 `CURRENT_TASK.md` 与 `TEST_REPORT.md`
- 所有项目修改（代码、配置、协议、表格、资源、场景、工具或文档）的修改说明统一写入项目根目录 `项目修改日志/`；项目解析、参考项目分析、架构设计、功能方案和专题使用说明统一写入项目根目录 `项目分析/`；不得在根目录或 `Docs/AI` 散落创建这些文件。
- `Docs/AI/` 仅维护四份协作入口记录，专题分析正文不放在其中；文档引用一律使用项目根目录相对路径。
- 新增或修改业务代码时，开发者必须为类型/接口、函数（含构造函数）、字段、属性、常量、事件、参数及局部变量补充具体中文注释；审查员必须将注释完整性作为代码规范门禁
- 任务结束后，参与角色必须输出变更摘要或分析结论，审查员输出审查结论，二者并存留痕
