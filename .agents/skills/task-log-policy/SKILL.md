# 任务日志按结果记录

结束任务前，根据本次实际变化判断“是否需要写入任务日志”，由 Agent 执行判断，不把每次判断变成向用户索要确认。

- 修改代码、配置、协议、数据表、资源、工具、技能或正式文档：需要记录。在 `项目修改日志/` 新建或更新本任务唯一完整日志；根目录 CURRENT_TASK / TEST_REPORT 只写本次编号、变化与验收边界、完整日志引用。
- 只有查找、方案或验证，但得到影响后续工作的新结论、可复用证据、新失败、阻断或交接信息：需要记录。按职责更新 QUERY_TASKS 或原任务 TEST_REPORT；没有文件变更就不额外新建修改日志。分析正文只放 `项目分析/`，协作入口不重复全文。
- 问候、确认收到、重复状态、已有证据足够的问答、输入未变且没有新事实的重复检查：不需要记录。回复说明“本次无需写入任务日志：没有新增持久事实”；不为“未写日志”再创建一条日志。
- 同一任务的进展和返修更新同一编号与原日志；仅有新的独立交付才新建任务记录。Git 回执只追加到完整修改日志，未改变验收输入时不反复同步所有入口。

写入内容限于：需求/任务编号、实际新增修改移动删除的逐项文件及用途、必要决策、真实验证结果和证据路径、失败/未验证边界、未解决问题和下一步；涉及 Git 时记录分支、提交范围与真实提交/推送结果。不得把历史“进行中”自动写成当前状态，或把归档视为已解决。

最终交付必须列出“本次是否写日志”以及实际新增/更新的日志路径和每份内容摘要；没更新的入口不冒称已写入。常见职责如下，只按实际需要选择：

| 记录 | 保存内容 |
|---|---|
| `项目修改日志/本任务.md` | 完整文件清单、修改原因、验收、未决问题、Git 回执 |
| `Docs/AI/CURRENT_TASK.en.md` / `.md` | 当前变化、未完成项、续作入口 |
| `Docs/AI/TEST_REPORT.en.md` / `.md` | 真实检查、失败证据、未验证边界 |
| `Docs/AI/QUERY_TASKS.en.md` / `.md` | 新的只读调查结论、证据路径 |
| `Docs/AI/DECISIONS.en.md` / `.md` | 影响后续实现的长期决策，按需更新 |
| `Docs/AI/PROJECT_CONTEXT.en.md` / `.md` | 稳定结构/规则变化，按需更新 |
| `项目分析/` | 正式分析正文；实际难点按项目要求记录 |
| `_temp/` | 本地原始工具输出和临时证据，不充当正式修改日志 |

仅读取缺少的上下文：先搜相关英文入口标题；缺失时搜 `项目修改日志/协作记录归档/2026-10-26/INDEX.md` 并读取命中原行段，不在每次启动扫描历史或两种语言。日志迁出活动入口前保留原文、任务编号、检索位置与校验信息；只删除确认重复且有恢复来源的内容，不清理 `_temp`。双语新增/修改内容按项目规则交子 Agent 增量同步和检查；未同步如实列为未完成。
