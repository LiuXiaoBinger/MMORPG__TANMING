# 任务日志先列清单，再询问开发者


## 每次任务固定入口与收尾

- 开始任务时，先读取或按主题检索 `Docs/AI/RECORD_INDEX.md`，找到与任务有关的主题/编号、源文件和行号范围，再仅取命中行段。不得为寻找背景先加载四份任务记录全文；没有相关记录就处理当前需求，不扩大为全量历史扫描。
- 每次任务完成后，在已获批准的记录写入、双语同步完成后运行一次 `python .agents/skills/task-log-policy/scripts/build_record_index.py`，更新目录的标题、编号、行段和源摘要。未写任务日志也要执行；源记录没有变化时，目录保持相同，不添加时间戳、空任务或额外流水。
- 目录生成是本地机械维护，只向上下文返回短结果，不把四份源正文输出给 Agent。读取时发现目录缺失、标题或行号不符，应先重建再取段。
- 目录更新独立于正式任务日志确认：更新现有记录的定位信息不等于获准新增任务日志，仍须遵守下方开发者确认流程。


每次任务完成后，Agent 先根据实际变化提出日志建议，列出拟新增/更新的具体路径、每份拟写内容、写入理由及未验证边界，再明确向开发者询问“本次是否写入这些任务日志？”。收到明确答复前，不更新正式任务日志或协作流水；等待时间不代表同意。

开发者已明确要求本任务写日志，或已批准这份清单时，沿用该授权，不重复询问。未明确时不得将普通开发、修改技能、提交或推送授权推断成同意额外日志。用户本次直接要求修改的业务文件、技能/规则文件照常完成；本确认只针对额外的任务记录，不阻断授权工作本身。

- 修改代码、配置、协议、数据表、资源、工具、技能或正式文档：建议记录。开发者确认后，在 `项目修改日志/` 新建或更新本任务唯一完整日志；根目录 CURRENT_TASK / TEST_REPORT 只写本次编号、变化与验收边界、完整日志引用。
- 只有查找、方案或验证，但得到影响后续工作的新结论、可复用证据、新失败、阻断或交接信息：建议记录。开发者确认后，按职责更新 QUERY_TASKS 或原任务 TEST_REPORT；没有文件变更就不额外新建修改日志。分析正文只放 `项目分析/`，协作入口不重复全文。
- 问候、确认收到、重复状态、已有证据足够的问答、输入未变且没有新事实的重复检查：建议不写。说明没有新增持久事实，并询问开发者是否仍需记录；不因询问、拒绝或“未写日志”再创建一条流水。
- 同一任务的进展和返修更新同一编号与原日志；仅有新的独立交付才新建任务记录。Git 回执只追加到完整修改日志，未改变验收输入时不反复同步所有入口。

写入内容限于：需求/任务编号、实际新增修改移动删除的逐项文件及用途、必要决策、真实验证结果和证据路径、失败/未验证边界、未解决问题和下一步；涉及 Git 时记录分支、提交范围与真实提交/推送结果。不得把历史“进行中”自动写成当前状态，或把归档视为已解决。

最终交付区分“已写入”“待确认”“开发者决定不写”，列出实际或拟写日志路径及每份内容摘要。待确认清单可以保留在 `_temp/` 供审阅，不先写入正式日志再补问；拒绝时不新增正式记录，没更新的入口不冒称已写入。常见职责如下，只按实际需要选择：

| 记录 | 保存内容 |
|---|---|
| `项目修改日志/本任务.md` | 完整文件清单、修改原因、验收、未决问题、Git 回执 |
| `Docs/AI/CURRENT_TASK.en.md` / `.md` | 当前变化、未完成项、续作入口 |
| `Docs/AI/TEST_REPORT.en.md` / `.md` | 真实检查、失败证据、未验证边界 |
| `Docs/AI/QUERY_TASKS.en.md` / `.md` | 新的只读调查结论、证据路径 |
| `Docs/AI/DECISIONS.en.md` / `.md` | 影响后续实现的长期决策，按需更新 |
| `Docs/AI/PROJECT_CONTEXT.en.md` / `.md` | 稳定结构/规则变化，按需更新 |
| `项目分析/` | 正式分析正文；实际难点按项目要求记录 |
| `_temp/` | 本地原始工具输出和临时证据，不充当正式修改日志 |

仅读取缺少的上下文：先在 `Docs/AI/RECORD_INDEX.md` 搜主题/编号，再按源路径和精确起止行号读取；不先读四份正文。修改四份英文源记录后运行 `python .agents/skills/task-log-policy/scripts/build_record_index.py` 更新目录，可用 `--check` 检查是否过期；标题或范围不符时先重建。缺失时搜 `项目修改日志/协作记录归档/2026-10-26/INDEX.md` 并读取命中原行段，不在每次启动扫描历史或两种语言。日志迁出活动入口前保留原文、任务编号、检索位置与校验信息；只删除确认重复且有恢复来源的内容，不清理 `_temp`。双语新增/修改内容按项目规则交子 Agent 增量同步和检查；未同步如实列为未完成。
