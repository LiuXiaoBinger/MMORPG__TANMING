# 服务器逻辑时钟丢失不足毫秒的余量

用户在编辑器地面反复按F仍提示“当前状态无法施法”。当前客户端已实际发送九个10080请求，运行中的两端程序集都含最新特殊技能分支；不能把此问题归因热更旧代码。

只读当前GameServer进程堆确认角色1在线、Job1、HP1000/MP500，基础组件、技能列表和背包保存数据均已加载。第一次F活动UUID1/10080，结束Tick为22；相隔16秒的两次实际进程采样，GameGlobal.LogicTick仍为10。所以第一次F已被接受，后续请求因服务器旧活动未到期返回状态拒绝，CD也随该逻辑时钟停住。

GameServerApp以无等待的循环调用GameGlobal.Update。旧Update把当前刻度差换算成long整毫秒，然后无论是否得到一毫秒都将采样原点覆盖为当前刻度。高速空循环的间隔大多不足一毫秒，每次都得到零并丢掉这段时间，逻辑50ms固定帧无法正常累积。

最小修复仅在GameGlobal.Update推进已计入的整毫秒原点：`_lastUpdateTimestamp += deltaMilliseconds * Stopwatch.Frequency / 1000`。不足一毫秒的刻度留给下次采样，原20Hz固定帧、最大追赶帧数、管理器更新、技能/CD的Tick结算均保持。没有新字段、等待、队列、校验或时钟框架，不靠放开滑步自断掩盖计时故障。

之前独立组件专项通过只说明手动推进Tick时技能结算正确，没有覆盖此真实忙循环时钟。角色未完成背包加载也会返回状态拒绝的独立实验与这次现场无关，不据此删除加载门禁。

验证使用隔离进程的真实GameGlobal.Update高速连续调用，对比before/after逻辑Tick及真实角色滑步自然到期、CD和后续释放；具体结果记录在`项目修改日志/2026-10-12-ROLL-STATEBLOCKED-FIX-CHANGELOG.md`，证据`_temp/roll-stateblocked-20261012/`。当前运行用户服务器不改内存、不自动重启；正式部署需重新编译并重启GameServer。

末稿服务端编译零错误，开发与独立主循环对比均证实before运行1200ms只推进1Tick而after推进25Tick，7项断言通过，原667ms动作/500ms CD自然结束且第二F成功。独立审查与主输入SHA核对通过，测试无真实网关，不计正式联机验收。
