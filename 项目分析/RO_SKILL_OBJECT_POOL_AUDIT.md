# RO 技能对象池与自定义类盘点

## 参考来源与范围

参考 `F:/UnityPro/ro/Ro_cs422nb/clientcode/CSProject/MoonCommonLib/Utility/MObjectPool.cs` 和 `MoonClient/Skill/MSkillFactory.cs`。检查本项目客户端新增场景实体、技能、UI 快照以及服务端技能类和相关运行时类。原表格、场景、资源和用户既有代码保留。

RO 的 `MObjectPool<T>` 使用创建委托、借还回调和空闲栈；`MCommonObjectPool<T>` 为具体类型提供共享入口；`MListPool<T>` 在借出及归还时清空列表。类型按项目要求拆成同名独立文件、使用全局命名空间和中文注释，缺失的 RO 日志接口适配 Unity 日志。

## 盘点与处理

| 对象 | 生命周期与处理 |
| --- | --- |
| `MSkill` | 每次施法由工厂借出；动作退出后仍归旧实例列表持有；拒绝、结束、超时、技能移除或清场时清理并归还。 |
| `MSkillCore` | 工厂借出，技能字典持有；存活施法还持有升级前核心，最后一个持有者解除后归还。 |
| `MSkillData` | 配置装配时借出，核心独占；核心最终清理时重置归还。它是当前项目运行时适配数据，RO 原表现数据还包含缓存共享，不能宣称所有数据机制原样一致。 |
| `MSkillPrediction` | 每次预测借出；确认、取消、超时或核心清理时归还；升级时转移引用并清空旧列表，禁止双重所有权。 |
| 临时技能快照列表 | 使用 RO `MListPool<T>`；结果数据由核心接管，列表容器归还时仅清引用。 |
| 场景实体、普通组件、动作状态 | 已有 `MEntityPool`、`MComponentMgr` 借还入口，继续使用既有池。 |
| 模型、Animator、同步事件参数 | 已有 `MModelMgr`、`MAnimatorPool`、`MEventPool`；不重复建立通用池。 |
| `SkillViewData` | 两个窗口以及异步 UI 回调可能同时持有；刷新后不能独占回收，保持不可变快照。 |
| Builder、事件处理器、资源租约、ClipInfo | 构建工具、组件绑定对象或异步共享资源缓存；本次不改变它们的现有生命周期。 |
| 服务端角色技能组件、Handler | 随在线角色或注册表长期存活，当前已有复用周期，无逐次施法借还需求。 |
| 服务端 protobuf 结果及通知 | 由调用方序列化并广播；缺统一重置和归还契约，保留现有生成协议边界，不引入跨调用复用。 |
| 服务端新增场景实体框架 | 尚未接入实际世界运行入口；需接入时确定实体重置及 UID、组件所有权契约，不能用未运行框架声称已池化。 |

## 核心持有适配

当前项目已有等级替换和旧施法列表，施法实例继续引用升级前核心。引入池后立即归还旧核心会让新租借污染仍存活的技能。因此核心保存字典和施法实例的持有数量，最后解除时归还；这是本项目池化的必要生命周期适配，不是 RO 原 `MSkillCore` 的逐字实现，不添加玩法、协议或键盘操作。

RO `Clear` 清空空闲栈而不扣减 `countAll`，本轮按其统计语义保留；清空后 `countActive` 不可当作实际未归还数量。验证借还平衡需在未调用池 `Clear` 的完整周期内观察。
