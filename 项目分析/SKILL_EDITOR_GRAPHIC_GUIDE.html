编辑器定位与整体架构

ACT 技能编辑器是一个固定 MIT 的嵌入式动作编排包 com.ethan.act-action-editor（v0.2.0-preview.2，Unity 2023.2），在本项目中被拆成五部分协作：嵌入包提供运行时数据与播放器，宿主工程提供编辑桥接与导出发布，另有独立只读验证程序集对构建结果做回归验收。

1.1 五部分职责一览

嵌入包 Runtime
程序集 Ethan.ActionEditor.Runtime：SkillConfigSO 数据资产、ActionPlayer 帧时钟、校验器、位移解算与 HitFeel。全平台、无外部程序集引用。
嵌入包 Editor（已迁出包体）
程序集 Ethan.ActionEditor.Editor：SkillEditorWindow 时间轴编辑器。包体内没有 Editor 目录，代码实际寄宿在宿主 Assets 下。
宿主编辑桥接
程序集 LYF.SkillAuthoring.Editor：绑定资产、资产生成、身份/字段校验、发布运行 SO、施法规则两端 JSON 导出。
运行时技能 / 配置资产
GM_Game 运行程序集：SkillRuntimePresentation 运行表现 SO、施法规则 SO 与 Resources JSON、YooAsset DefaultPackage 收集组。
独立验证程序集
程序集 LYF.SkillAuthoring.Verification.Editor：只读调真实 YooAsset 模拟构建 + 实际打包/加载技能依赖 Bundle 子集，不建角色、不改场景。
!
包不是自包含的：Editor 程序寄宿在宿主工程

包目录 Packages/com.ethan.act-action-editor/ 下只有 Runtime / Integrations / Samples~ / Tests，没有 Editor 目录。但宿主桥接 asmdef 引用了 Ethan.ActionEditor.Editor，该程序集实际位于 Assets/GM_Game/Editor/Skill/ActionEditor/（含 Infrastructure / Timeline / Window 子目录）。升级嵌入包时不能只替换 Packages 目录，这条寄宿关系必须随包一起维护。

ActionEditorAgent 自动化编辑公开接口（强类型 DTO，禁止 object 载荷）：

  • Request：schemaVersion(1|2)、operation、assetPaths[]、outputAssetPath、animationAssetPath/ClipName、displayName、exitFrame(-1推导/0自动/正数)、expectedDigest(SHA256)、dryRun、edits[]。
  • Result：success、issues[]（code/severity/track/eventIndex/message）、contentDigest、fields[]、changes[]。
  • 编辑流程：克隆副本 → ApplyEdit(set/insert/remove/move) → 校验 → SHA256 比对 expectedDigest → Undo 分组提交/失败回滚；对象引用按 GUID+localFileId 解析。
  • 白名单：Allowed(path, writing)——首段必须是 SkillConfigSO 公开字段；写入时禁止改 timingVersion/timelineFrameRate；播放中拒绝操作。

2.9 易混淆点与源码疑点

!
Sound 轨与 Fx 轨显示名完全相同
两轨 localizedName 都是 Effect/特效，靠「是否展开 + 内容过滤」区分（BuiltinTrackRegistry.IsVisibleInFxTrack/IsVisibleInSoundTrack），界面上极易混淆，疑似历史遗留。
i
fxDef / moveDef 的初始 lanes 是死代码

10.4 常见问题（FAQ）

Q1：点了“保存”，为什么游戏里技能表现没变？

保存只写 Authoring 资产。必须再点绑定 Inspector 的“校验并导出当前表现”（或“校验并导出全部表现”），生成 Runtime SO 后游戏才会读到新数据。

Q2：为什么我在位移/镜头/判定轨道加了内容，导出直接失败？

这些轨道在编辑器中完整保留，但运行时尚未接入；导出器对全部序列化字段（含隐藏轨道）做白名单校验，非默认数据会阻止发布，避免“编辑器里做了、游戏里不生效”的假象。清空为默认即可导出。

Q3：InteruptSkill 列表到底填谁？

填在新技能那一行，列表里写该新技能可以打断的旧技能 ID。例如在 10040（E）行填 10010（Q），表示 E 可打断 Q；反向不会自动成立，需要在 Q 行另行配置才成立。

Q4：MoveCasting=true 后为什么还是不能跳？

MoveCasting 只放开水平移动；技能期间主动起跳被固定禁止，空中重力与落地照常。当前也没有“跳跃取消技能”的协议与字段。

Q5：TargetTop 定位在编辑器里怎么预览？

在工具栏指定“预览目标 / Preview target”；未设目标时会明确提示并按角色前方距离兜底。游戏运行时使用实体模型高度，编辑器预览使用渲染边界高度，两者可能有差异，目标头顶表现需实机核对。

Q6：NamedSocket 的路径怎么填？填错会怎样？

填完整 Transform 路径（如 MJS 的 hand_r 路径 root/pelvis/spine_01/.../hand_r）。解析器先查精确路径，仅已确认的旧 JX 右手路径映射到当前 Avatar 的 RightHand；未知、缺失或有歧义的路径直接拒绝，不会猜测取首项。

Q7：服务端需要随技能表一起重新出吗？

技能表现资产只在客户端；但施法规则 JSON 两端同源，改规则后要重新导出并把游戏服 Config 下 JSON 随构建部署、重启服务。服务端不读取客户端资产，也不从开发机绝对路径找规则。

Q8：粒子为什么在技能结束后还短暂存在？

这是设计行为：粒子实例由 SkillRuntimeFxLifetime 独立持有资源租约，以真实尾粒 IsAlive(true) 判定结束，尾迹播完才销毁并释放租约，避免特效被提前截断。
