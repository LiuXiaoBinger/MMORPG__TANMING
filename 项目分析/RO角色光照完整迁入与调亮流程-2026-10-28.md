## 1. 先把结论放前面

1. **角色光照的完整链已经迁入并且能跑**：`MEnvorimentSetting`（适配）+ `MDayTimeData` / `MCreatureLightData` /
   `MEnvorimentData` / `MAmbientData`（复制/裁剪）+ 三套原版数值配置资产 + 原版 `DOTween.To` 2 秒插值路径 + 原版 Shader（未改一字）。
   不再是"只把四个 Color 塞进 Shader 全局量"的残缺版本。
2. **`_Brightness("光强")` 在 RO 里没有任何消费者**：Shader 只声明不读（`ROPlayer__beta153.shader:33` 声明、
   `CreatureCommon.cginc:230` 声明、全文无读取），C# 侧唯一同名引用是后处理（`MPostSetting.cs:238`），
   也没有 Creature 的自定义 ShaderGUI。实测把它从材质实际值 1.390 改到 0 或 2.0，角色像素 **0 变化**（最大通道差 0）。本轮没有把它乘进最终颜色。
3. **真正能调亮的入口**（r2 实测，见 §5）：
   - 换时段配置（RO 的正常工作流）：白天/黄昏/夜晚 → 0.1647 / 0.1522 / 0.1199；
   - `MCreatureLightData.backLightColor.rgb` 整体缩放 → ×0.35 得 0.0990（60.1%），×1.7 得 0.2415（146.6%），且能在 Inspector 里手输；
   - `ambientColor.a`（环境替换比例）1→0 → 93.1%；
   - 材质 `_Falloff`（明暗分界）→ 98.5% / 105.7%；
   - `reflectMap`（源反射立方图）接回后整体 +17.3%（0.1405 → 0.1647）。
4. **反直觉但真实（限定于当前模型/配置）**：把 `mainLightColor.rgb` 置黑，角色**平均**亮度几乎不变（0.1656 vs 0.1647）。
   原因是 Shader :1088 的 `directBack = lerp(_ROCBackColor.rgb, max(0, 1 - directFront), NoL)` 会把消失的直射补偿回来。
   **不能由此推广成"主光 RGB 只有色相影响"**：:1100 的直射项仍是 `mainLightColor.rgb` 直接乘进最终颜色，
   单像素确有变化（9,268 像素、最大通道差 46），只是平均被补偿抵消。换模型/换 `cl_*` 数值后需重测。
5. **`ambientIntensity` 不是角色亮度旋钮**：Flat 下改它（0.25/2.5）角色与地面都 0 变化；Skybox 下它对普通材质有效
   （地面 0.3146 → 0.5643），但角色仍 0 变化，因为角色 Shader 在 `ambientColor.a=1` 时把环境项整体换成了 `_ROCAmbientColor`。
6. **编辑态不做插值采集**：编辑态没有运行时循环，DOTween 不会自己推进，本版 DOTween 也没有可枚举/定位 tween 的公开接口；
   2 秒插值的证据全部来自 Play 模式按真实经过时长采样（0.450 s / 1.000 s / 2.404 s，终点与立即应用 0 像素差）。

## 3. 角色 Shader 消费顺序（`CreatureCommon.cginc`）

| 行 | 代码 | 作用 |
|---|---|---|
| :552 | `sh += max(const_v30, ShadeSH9(worldNormal))` | 球谐环境 |
| :560 | `o.lightSH = lerp(sh, _ROCAmbientColor.rgb, _ROCAmbientColor.a)` | 环境色替换 |
| :660 | `half3 lightDir = _ROCLightDir0` | 主光方向 |
| :676-677 | `cosTheta.x = dot(lightDir, normalDir)`；`liten = smoothstep(_Falloff.x, _Falloff.y, cosTheta.x)` | 明暗分层（材质 `_Falloff`） |
| :875 | `atten = 1 - atten`（阴影采样在源里是注释掉的，atten 恒 1） | 无自阴影 |
| :883 | `f.NoL = liten * atten` | 进入片元的 NoL |
| :1014 | `diffuseTerm = DisneyDiffuseRO(...) * saturate(i.NoL)` | 漫反射项 |
| :1085-1090 | `directFront = 2*_ROCLightColor0.a*_ROCLightColor0.rgb`；`directBack = lerp(_ROCBackColor.rgb, max(0,1-directFront), NoL)`；`ambient = lerp(i.ambient, directBack, _ROCBackColor.a)`；`lightColor = _ROCLightColor0.rgb` | 直射/背光/环境三者 |
| :1099-1104 | `col = 0 + diffuse*(diffuseTerm*lightColor) + spec + indirectDiffuse*occlusion + specIBL + emission` | 最终色 |
| :483 | `f.rim = (_ROCRimColor.rgb*2-1)*_ROCRimColor.aaa` | 顶点插值量，**片元无消费者** |

由此可以解释实测现象：`mainLightColor.rgb` 只进 :1100 的直射项，而 :1088 会用 `1-directFront` 顶替背光，
两者在本路径上几乎互相抵消；`backLightColor` 同时决定 `directBack`（:1088）和它的混合权重（:1089），
所以是这条路径上的"亮度总闸"。这不是 Demo 的适配偏差，而是原版公式的直接结果。

### 6.2 资产层
- **配置资产是按字段重建的，不是直接拷贝**：源 `.asset` 的 `m_Script` 指向 `guid c7d8e4bb082ba21419cc6eeac3c88988`
  （`MDayTimeData` 与 `MCreatureLightData` 两个类在同一 MonoScript 的两个 fileID 上：`41332261` 与 `-1677881894`）。
  这两个类型在源工程里是**打包好的 `MoonSerializable` 程序集**（`clientproj/Assets` 下没有对应 `.cs`/`.meta`），
  本工程没有那个程序集，直接拷 `.asset` 会变成 Missing Script。因此用 `ROConfigAssetBuilder` 以迁入的同名类型重建资产，
  字段值与源 YAML 一一对应（脚本里逐条注释了每个数值的出处）。
- **`reflectMap` 已接回**（第 2 轮更正第 1 轮的错误结论）：按 guid `564fd75e804da2e46babf53b494f35cb` 搜源工程 `.meta`，
  命中 `clientproj/Assets/artres/_GameRes/Scenes/Common/Skybox/Hdr01.jpg.meta`（`textureShape: 2` Cube，1024×1024）。
  第 1 轮"全工程搜不到 → 在 AB 包内"的判断是搜索方式错误（只搜了 `SceneEnviroData` 目录），应如实记为"当时没找到"，

### 6.4 `ambientIntensity` 的真实语义（第 1 轮写错，此处更正并给实测）

第 1 轮在 `MAmbientData.ambientIntensity` 的注释和 README 里写"它乘在环境项上，因此会改变角色暗部亮度"，
以及"Flat 下乘常量环境色"——两者都没有依据。`RenderSettings.ambientIntensity` 的真实语义是
**Skybox 环境光倍率**：只对 `ambientMode = Skybox` 下"由天空盒生成的那份环境光"生效。
它**不是** `reflectionIntensity`（反射立方图对镜面反射的强度），也和 `defaultReflectionMode` / `customReflectionTexture`
那条反射链无关——第 2/3 轮一度照抄文档里"天空盒或自定义反射探针"的措辞，容易把两者混为一谈，此处收口。
Flat 用的是常量 `ambientLight`，Trilight 用 Sky/Equator/Ground 三色，两者都不走 `ambientIntensity`。

r2 对照实测（其余输入全部固定，`_temp/ro-character-full-verify-r2.json` → `ambientIntensityProbe`）：

| 模式 | 改动 | 角色平均亮度 | 地面区域（下方 30%，Standard 材质） |
|---|---|---|---|
| Flat | intensity 1 → 0.25 | 0.164698 → 0.164698 | 0.233053 → 0.233053 |
| Flat | intensity 1 → 2.5 | 0.164698 → 0.164698 | 0.233053 → 0.233053 |
| Flat | `ambientSkyColor` × 0.5 | 0.164698 → 0.164698 | 0.233053 → **0.191101** |
| Skybox | intensity 1 → 2.5 | 0.164547 → 0.164547 | 0.314615 → **0.564334** |

结论：**Flat 改 `ambientSkyColor`、Skybox 用 `ambientIntensity`**（对吃 SH 的普通材质成立）；
**角色在 `ambientColor.a=1` 时对这两者都无反应**，因为 `CreatureCommon.cginc:560` 用 `_ROCAmbientColor` 覆盖了 `ShadeSH9` 结果。
要改角色暗部就改 `cl_*.ambientColor`（a 1→0 时角色亮度 0.1647 → 0.1534）。

### 6.5 反射链的真实消费者（第 1 轮"只影响 matcap"的判断作废）

`CreatureCommon.cginc` 里反射不是 UTS2 matcap 分支，而是标准 PBR IBL：

```
:1051  indirectSpecular = ReflectionIBL(UNITY_PASS_TEXCUBE(unity_SpecCube0), unity_SpecCube0_HDR, i.reflDir, mipLevel);
:1063  indirectSpecular *= SurfaceReduction(roughness2);
:1103  col += (indirectSpecular * surfaceReduction * FresnelLerpRO(specular, grazingTerm, diffuseNoV)) * occlusion;
```

`unity_SpecCube0` 来自 `RenderSettings.customReflectionTexture`，而后者只有在 `defaultReflectionMode = Custom` 时才被 Unity 采用。
因此：`cl_*.reflectMap` → `RenderSettings.customReflectionTexture`（源 :523）→ `unity_SpecCube0` → `indirectSpecular` → 最终颜色。
只改 `reflectMap`（on/off）实测：0.164698 vs 0.140486（+17.3%），85,684 像素变化、最大通道差 57。

### 6.6 插值依赖与"编辑态不假装播放"

- 依赖：源 `Assets/Demigiant/DOTween/DOTween.dll` 原样复制（不迁 DOTweenPro、DOTween43/46/50、Modules 示例），
  `.meta` 也照抄（保留 guid）；`DOTween.dll` 的插件设置是 `Any: enabled 1` + `Editor: enabled 0`（后者只是"不覆盖"，
  与 `LYF_MMO` 里在用的那份一致），编辑器内可正常加载。
- 编辑态：没有运行时循环，tween 不会自走；本版 DOTween 也没有"枚举活动 tween / 按已播时长求值"的公开接口
  （实测 `DOTween.PlayingTweens(List<Tween>)` 在该版本不存在重载，`TotalPlayingTweens` 只返回计数）。
  因此**编辑态只支持立即应用**，验证器不做任何手动推进，也不再产出"手推时间步"的插值截图。
- Play 态：`RunPlayMode()` 用 `EditorApplication.timeSinceStartup` 记录真实经过时长，在 0.45 s / 1.0 s / 2.4 s 采样，
  实测 0.120466 → 0.138630 → 0.154266 → 0.164755，终点与"立即应用白天" **0 像素差**。

### 6.7 颜色字段的 Inspector 可编辑性（不是原版功能）

源 `MCreatureLightData` 没有 Inspector 特性，普通 `ColorField` 会把输入夹在 0~1，用户没法手输 1.49 这种 HDR 值。
本轮只加 `[ColorUsage(true, true)]`，并用 Inspector 同一条数据通路验证可持久化：
设 `backLightColor=(1.4933,1.4000,1.4933,0.8941)` → 存盘 → 强制从磁盘重导入 → 读回仍是 1.4933，
`.asset` 里写着 `{r: 1.4933333, g: 1.4000001, b: 1.4933333, a: 0.89411765}`；应用后角色亮度 0.241479（与代码赋值的 0.241475 一致）。
**这不是原版已有的亮度滑杆**，只是让既有的 `backLightColor` 能在 Inspector 里输入源数值。
