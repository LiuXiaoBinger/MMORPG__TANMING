## 一、30 秒项目介绍

这是一个 Unity 2023.2 + C# 的 3D MMORPG 项目。客户端用 YooAsset 做资源热更、HybridCLR 做代码热更；服务端是 Login / Gate / Game / Center 四服，TCP + Protobuf 通信，配置用 Luban。这一轮我重点打通了四块：技能释放链、技能动画与位移、技能编辑器导出发布、多角色移动与施法同步。技能系统本身参考了 RO 的职责划分，再按本项目做接入适配。要注意的是：目标命中与伤害结算、移动的服务器物理权威、AOI 和大规模压测都还没做，这些不能当成果讲。

**这个项目主要解决三件事：**
- 出招要跟手，但消耗和 CD 不能由客户端说了算 —— 用预表现 + 服务端 TryCast 权威。
- 策划做的特效不能“编辑器里有、游戏里没有” —— 用导出契约 + 运行时按毫秒时钟播放。
- 多个位移来源不能互相打架、远端要能看到我动 —— 用统一位移消费 + 影子追赶。

**我的职责范围：** 客户端技能生命周期与预表现、位移消费接入、编辑器导出接线，以及服务端 TryCast 校验链与移动广播的接线排查；YooAsset / HybridCLR / Protobuf 是直接用的，RO 技能职责是参考只读核对，不是我从零写的。

| 层 | 选型 |

| 服务 | 端口 | 一句话职责 |
| --- | --- | --- |
| CenterServer | 10110 | 查库、数据下发（如已学技能）、跨服中枢 |
| LoginServer | 10120 | 登录认证 |
| GameServer | 10130 | 业务逻辑权威：TryCast 校验、扣 MP/CD、移动更新与广播 |
| GateServer | 10140 | 会话接入，转发客户端与 Game 之间的消息 |

**一次登录怎么把技能装到客户端：** Center 按 RoleID 查 `game_db.role_skill` → 组 11080 已学技能 → Game 校验在线后转发客户端 → 客户端 `ApplySkillCores` 对每个 Level>0 的技能 `OnAttachSkill` → `MSkillFactory.CreateCore` 按 (skillId, level) 查效果行。之后按键才走 11170。

**20Hz 怎么产生：** Stopwatch 测真实经过时间累加到毫秒，每满 50ms 推一个 Tick，每轮最多追赶 5 帧、余量不丢；网络收包在主循环先跑，不等 Tick。所以“服务器 Tick 频率”“收包时机”“客户端发包频率”是三件事。

**四服为什么这么分：** Login 只管认证、Gate 只管接入转发、Game 持有业务权威、Center 管查库与跨服；这样 Game 不用直接面对海量长连接，也便于按业务扩缩。

> ⚠️ **边界：** 服务端 20Hz = 每 50ms 一次业务固定步长（Stopwatch 累积、最多追赶 5 帧），这是服务端逻辑时钟，不是客户端确定性锁步，不能讲成帧同步。

## 三、三个核心亮点

> 每个亮点按“背景一句 → 方案要点 → 验证/边界”讲；关键文件最多留 2~4 个，面试时不必全背，能指出在哪就行。

### 亮点一：技能预表现 + 服务端权威校验

**背景：** 玩家按技能要立刻看到出招，但能不能放、扣多少蓝、CD 多久不能由客户端自己决定。

**方案要点：**
- 长期 `MSkillCore`（按已学等级 + 配置）与单次施法实例 `MSkill`（带 SkillUuid、本次时钟与生命周期）分离。
- 按键先本地预判（跳跃 / 已学 / MP / CD），通过后取 `NextSkillUUID` 发 11170；发包无异常才 `BeginPrediction` 启动本地 CD 与表现，发送异常不预表现。
- Game 单逻辑线程 `ROSkillComponent.TryCast` 依次校验装载 / 存活 / 状态 / 学习等级 / 职业 / 配置 / 单 CD 组 CD / MP；通过才扣 MP、写 CD 截止 Tick。
- 先回 11170 Ret 给施法者本人，再广播 11171 开始、结束发 11173。
- 回包按 SkillUuid 校正 CD（截止时间减服务器时间转秒）与 MP；`cmd_code` 失败则 `Cease(true)` 立即停预表现，按服务器快照校正。

```text
按键 → 本地预判通过 → 取 NextSkillUUID 发 11170
     → Game TryCast 校验 → 扣 MP / 写 CD
     → 回 11170 Ret 给本人（权威 MP/CD/段号）
     → 广播 11171 开始 → 结束广播 11173
本人按 UUID 确认预表现；拒绝则 Cease(true) 停表现并按快照校正
```

**TryCast 校验收缩版：** 技能已装载 → 角色在线存活 → 当前状态不互断 → 已学该技能且等级 >0 → 职业匹配 → 配置存在 → 单 CD / 组 CD 未到 → MP 足够。任何一道不过就拒绝，不提前扣蓝、不推进段号。

> ⚠️ **边界：** 只打通准入、消耗与表现链；目标命中、伤害、Buff 都没做。

关键文件：`LYF_Server/GameServer/Components/ROSkillComponent.cs`、`LYF_Server/GameServer/MessageHandler/Skill/SkillCastHandler.cs`、`LYF_MMO/Assets/GM_Game/Scripts/SceneEntity/Skill/MSkillFactory.cs`。

### 亮点二：技能编辑器导出与运行时播放契约

**背景：** 策划在编辑器里拖动画 / 特效 / 声音轨道，要变成游戏里真正会播的技能表现，不能“保存了就悄悄改游戏”。

**为什么要做：** 以前做特效常遇到“编辑器里看着对、包里白框”——根因是制作数据、导出支持、运行处理器和权威规则没逐项对上。这套契约就是把“作者稿存在”和“正式会执行”分成两件事，每一步都能单独验收。

**方案要点：**
- 作者稿 `SkillConfigSO` 与运行时 `SkillRuntimePresentation` 是两份数据；显式校验导出才更新运行表现。
- 事件按帧率把帧号换算成秒；`MArtSkill.FireEvents` 用毫秒时钟登记，到期才分派粒子 / 声音，不是每帧全量扫描。
- 模型冷加载时按条申请 GO：已就绪立即播，未就绪存可取消票据，打断 / 回池时撤销，避免旧动作晚到挂到新角色上。
- “编辑器里能跑”不等于“包里能跑”：要核真实 Bundle 里的 DLL 字节与方法 IL，缺 Shader 变体仍会白框。
- 为什么分两份数据：保存作者稿不能悄悄改游戏，导出这一步才是“发布”；预览采样和正式播放也分开职责，不让预览副本累积位移。

> ⚠️ **边界：** 已接入轨道有限；正式包 1071 未发布该成果，验证停在真实包读取与 Editor 层。

关键文件：`LYF_MMO/Assets/GM_Game/Editor/Skill/SkillEditorAssetTools.cs`、`LYF_MMO/Assets/GM_Game/Scripts/SceneEntity/Skill/MArtSkill.cs`。

### 亮点三：移动同步、根运动与统一位移消费

**背景：** 本地走位、技能根运动、击退 / 滑行程序位移、重力要合成一次移动；远端玩家还要能看到我在动。

**为什么要做：** 最初各来源各自 Move，结果互相覆盖、同帧双走；远端又看不到技能位移，只能等播完补移。把位移统一成“生产增量 → 一个 frameMovement → 一次提交”后，本地物理结果和远端表现才对得上。

**方案要点：**
- 本地输入、技能根运动（`SkillRootMotionCollector` 取 Animator 水平增量）、程序位移、重力都合进同一个 `frameMovement`，单次 `CharacterController.Move`，过本地碰撞。
- 远端 B 用 11181 存影子目标，`LagSyncUpdate` 自估速度逐帧追赶；有碰撞位移的帧跳过追赶，按碰撞后实际落点重算残差，避免同帧双走。
- 11180 是变化触发上报（不是固定 Tick），服务端更新 Pos 后按同图 100 米 `IsNearbyRole` 过滤广播 11181。
- 为什么合一次 Move：本地碰撞、根运动、程序位移如果各自 Move 会重复过碰撞、互相覆盖；合进一个 frameMovement 一次提交，物理结果才一致。

> ⚠️ **边界：** 服务器不校验速度 / 路径 / 穿墙，包里没有速度字段；远端影子追赶直写 Transform 不过碰撞是当前设计现状；没有 AOI、没有抖动缓冲。

关键文件：`LYF_MMO/Assets/GM_Game/Scripts/SceneEntity/Component/MMoveComponent.cs`、`LYF_MMO/Assets/GM_Game/Scripts/SceneEntity/3DModel/SkillRootMotionCollector.cs`、`LYF_Server/GameServer/Components/ROMoveComponent.cs`。

## 四、两个典型难点

> 每个难点按“背景一句 → 方案要点 → 验证/边界 → 为什么值得讲”；不要背全部类名，讲清因果链即可。

### 难点一：施法预表现、MP/CD 校正与拒绝回滚

**背景：** 客户端出招立刻给反馈，但又不能让客户端决定蓝量和冷却，还要在服务器拒绝时干净回滚。

**方案要点：**
- 表现实例回池时曾误调 `Core.Reload`，把合法 10 秒 CD 清成 0；定位到 `MSkill.Cease` 不该动核心 CD，删除该调用。
- 权威回包走 `OnSkillCoreSync`：用 `cooldown_end_unix_ms - server_time_unix_ms` 转秒校 CD，`ApplyAuthoritativeMp(current_mp)` 写回权威蓝量。
- 服务器拒绝时 `Cease(true)` 停本次预表现；因为拒绝时本就没扣蓝，所以没有单独的“返还 MP”逻辑，错误码经 `GetCastErrorText` 转中文提示。
- 迟到的旧段结果能收尾自己的旧表现，但不能覆盖新段的 MP / CD。

**排查思路：** 表现回池后 CD 变 0，先怀疑“谁在回池路径上动了 CD”，顺着 `MSkill.Cease` 追到误调的 `Core.Reload`；确认这是表现层不该碰核心层状态后删除，CD 完全交给施法与权威回包管理。

> ⚠️ **边界：** 输入链隔离 + 独立编译 280 源 0 错；未做真人联机。

**为什么这个难点值得讲：** 它暴露了“表现层”和“权威状态层”的边界——表现回池只是资源回收，不能顺手改服务器权威状态。修复原则是把 CD/MP 的写入口收拢到施法与权威回包，表现层只读不写。

### 难点二：远端影子追赶、根运动消费与重复位移

**背景：** 自己放技能看到位移正常，远端玩家却要等动画播完才“啪”地补过去。

**方案要点：**
- 修前远端根运动采集出来了但没人消费，技能期间普通追赶又被禁，于是位移拖到播完才补。
- 修后远端也走 `ConsumeDelta`，把根运动增量并入同一次碰撞移动；有位移的帧跳过影子追赶，并按碰撞后实际落点重算残差，防止同帧两次推动角色。

**排查思路：** 先确认根运动到底采没采出来——在远端侧打日志发现采集有值但没人消费；再确认为什么没消费：技能期间普通追赶被禁，这段根位移就“悬空”等到播完。补消费入口后还要加互斥，否则同一帧根位移 + 影子追赶会重复推动角色。

> ⚠️ **边界：** 原生 40 帧夹具测得 4.999855 米（理论）vs 4.999854 米（实际），独立编译 0 错；这是原生隔离数据，未双端联机。

**为什么这个难点值得讲：** 它不是“写个移动”，而是跨客户端两侧 + 服务端广播的状态一致性问题——本地看到位移正常，不代表远端正常；只改一侧会顾此失彼。最后用“统一消费入口 + 互斥 + 按落点重算残差”三条一起解决，单改任何一条都不够。

## 五、一页 ID / 协议对照

**两个易混点先记住：**
- 11080 = 进世界时装载的已学技能列表；11170 = 按键时才发的施法请求/结果。不要把“装载”和“施法”讲混。
- SkillId（哪种技能，10010）≠ SkillUuid（这一次施法的临时身份，1~9999 循环）。

### 四类 ID 不要混

| 层级 | 表 / 类型 | 主键 | 例子 | 说明 |
| --- | --- | --- | --- | --- |
| 技能主表 | SkillInfo（tbskillinfo） | Id | 10010（Q） | 长期身份：Type / CD / 耗蓝 |
| 等级效果行 | SkillEffectInfo（tbskilleffectinfo） | Id（稳定效果 ID） | 2001001 | SkillId+Level 查询，TryCast 权威规则 |
| 表现行 | SkillPresentationInfo | Id | 3001001 | EffectId+ProfessionId，动画 / 特效，可空 |
| 施法身份 | SkillUuid（uint64） | — | 1~9999 循环 | 随施法包原样带回，匹配预表现与回包 |

> ⚠️ 2001001 是效果表主键，不是主表技能 ID；`GetComboReplaceSkillID` 返回的也是效果表 Id。

### 协议简表

| 协议号 | 方向 | 用途 |
| --- | --- | --- |
| 11070 | C→S | 进世界请求 EnterWroldReq |
| 11080 | S→C | 已学技能列表（进世界装载） |
| 11090 | S→C | 主角进世界数据同步给其他在线玩家 |
| 11100 | S→C | 其他在线角色同步给主角 |
| 11170 | C↔S | 施法请求 / 仅回本人权威结果（同号双向） |
| 11171 | S→附近 | 施法开始广播（含本人） |
| 11173 | S→附近 | 施法结束广播（interrupted 标死亡 / 断线 / 切图） |
| 11180 | C→S | 本地位置上报 |
| 11181 | S→附近 | 附近移动广播 |

- TCP 帧：`[2 字节小端长度][1 字节压缩标志][2 字节 CRC16][消息体]`，消息体 >200 字节 GZip，整包上限 65535。

> 📌 **协议号分组记忆：** 110xx 是进世界 / 在线角色同步；1117x 是施法链（请求回包 / 开始 / 结束）；1118x 是移动链（上报 / 广播）。讲的时候按组说，不要背单个号。
- 11170 Ret 关键字段：`current_mp` / `cooldown_end_unix_ms` / `group_cooldown_end_unix_ms` / `using_times`（段号）/ `effect_id`；11180/11181 只有坐标、朝向、耗时和两个 bool，**没有速度字段**。

| 11170 Ret 关键字段 | 类型 | 用途 |
| --- | --- | --- |
| cmd_code | int32 | Succeed 或错误码（失败走 Cease） |
| current_mp | int32 | 权威蓝量，回写本地 |
| cooldown_end_unix_ms | int64 | 单 CD 截止，减服务器时间转秒倒计时 |
| group_cooldown_end_unix_ms | int64 | 组 CD 截止 |
| using_times | int32 | 段号，选下一段表现 |
| effect_id | int32 | 效果行 Id，远端按它选表现 |

## 六、面试话术

> 1 分钟版是电梯陈述，3 分钟版是展开；口语化，可直接背。

### 1 分钟版

我做的是一个 Unity 2023.2 + C# 的 3D MMORPG，客户端用 YooAsset 做资源热更、HybridCLR 做代码热更，服务端是 Login、Gate、Game、Center 四服，TCP 加 Protobuf，配置用 Luban。我最熟的一块是技能系统：玩家按 Q 先做本地预判、立刻播动画给反馈，同时把请求发给服务器；服务器按已学等级真校验蓝量和冷却，通过才扣蓝写 CD，再回权威结果；回包按一个临时 UUID 找到那次预表现做校正，被拒绝就立刻停掉。这样出招跟手，又不会让客户端自己决定扣多少蓝。移动同步我做的是把本地输入、技能根运动、程序位移合到一次碰撞移动里，远端再用影子追赶看到。技能编辑器我接的是导出契约和运行时播放。边界是目标伤害、移动物理权威和大规模压测都还没做。

### 3 分钟版

**项目一句话：** Unity 2023.2 + C# 3D MMORPG，四服 TCP + Protobuf，Luban 配表，重点打通技能、位移、编辑发布和多角色同步，技能参考 RO 职责划分。

**三个亮点：**
- 技能预表现加权威校验：本地预判、无异常才预表现，服务器 TryCast 十一道校验后扣 MP 写 CD，回包按 UUID 校正、拒绝 Cease(true)，跟手又不失权威。
- 编辑器到运行时的契约：作者稿和运行表现两份数据，校验导出才生效，事件按毫秒时钟注册到期分派，模型冷加载按条等 GO，避免旧动作挂错人。
- 位移统一消费：输入、根运动、程序位移、重力合一次 CharacterController.Move；远端影子追赶直写 Transform，和碰撞移动互斥、按落点重算残差。

**两个难点：** 一是回池误清 CD 加权威校正，根因是 Cease 不该动核心 CD，删掉后由回包统一管 MP/CD；二是远端不消费根运动导致播完才补移，补 ConsumeDelta 并让有位移帧跳过追赶。

**收尾：** 这些结论分了验证层级——源码专项、独立编译、原生隔离、真实包回环、正式联机。我做到独立编译和原生隔离的部分居多，目标伤害、移动物理权威和大规模联机压测是下一步。

**下一步优先级（被问“接下来做什么”时答）：** 第一优先是补服务器移动物理权威（速度 / 路径 / 穿墙校验），因为当前远端是客户端自报终点；第二是接目标命中与伤害结算，把技能从“能放出来”推到“能打出结果”；第三才是 AOI 与联机压测。

> 🎤 **讲述顺序：** 先用 30 秒介绍项目 → 主动挑一个最熟亮点（建议技能预表现 + 权威校验）展开 → 被问“最难的”再讲两个难点里的一个（建议远端根运动消费）→ 每个讲完都补一句“边界 / 验证到哪层”。不要一口气把所有类名背出来，留钩子让面试官追问。

## 七、高频追问

> 下面这些是按“最容易被追问、最容易答过头”挑出来的，答案与详尽版一致，不夸大。表格一行就是一句可直接背的话。

| 追问 | 直接回答 |
| --- | --- |
| 状态同步还是帧同步？ | 位置状态上报 + 远端影子追赶；20Hz 是服务端业务步长，不是客户端锁步确定性。 |
| Send 返回 true 就是成功？ | 不是。只代表本地队列收下，预表现同调用开始；MP/CD 以权威回包为准。 |
| SkillId 和 SkillUuid 区别？ | SkillId 是哪种技能（10010）；Uuid 是这一次施法的临时身份，1~9999 循环，只匹配本次请求与回包，不是永久唯一 ID。 |
| 服务器校验移动速度 / 穿墙吗？ | 当前不校验。11180/11181 只有坐标朝向耗时和两个 bool，没有速度字段，物理权威是后续缺口。 |
| 编辑器对了为什么包还报错？ | Editor 用当前编译程序集，包用 YooAsset 里 TextAsset 的 DLL 字节；要核 Bundle 字节和方法 IL，重编 Editor 不能证明包里对。 |
| MP/CD 谁权威、拒绝怎么回滚？ | 服务器权威。回包 OnSkillCoreSync 校 CD、ApplyAuthoritativeMp 校 MP；拒绝 Cease(true)，拒绝时没扣蓝，无单独返还逻辑。 |
| 为什么不能动画播完就全释放？ | 动作结束可能还有服务器状态、未来事件和音尾；CD 由施法和回包管，回池只清表现资源。 |
| 根运动和影子追赶会不会叠加？ | 不会。有根位移的帧跳过影子追赶，并按碰撞后实际落点重算残差，避免同帧双走。 |
| 为什么预表现不用“等服务器回包再出招”？ | 等回包再出招会有 RTT 延迟，手感差；本项目用“本地预判 + 服务器权威 + UUID 校正”兼得，代价是要处理拒绝回滚和迟到回包，我们已经做了。 |
| 热更 DLL 引用主包没有的类型？ | 补 AOT 元数据没用（那是给已有 AOT 代码补元数据）；必须重打完整主包，资源热更补不了缺失原生程序集。 |
| 选敌怎么做、半径多少？ | 点击用相机射线（按下松开同一实体才选中）、Tab 在最近 4 个怪里循环、攻击 Type1/2 自动选；统一 18 米，和技能射程各自独立，只认 MonsterEntity。 |
| 大规模布尔重构怎么保证不改坏？ | 先写 Roslyn 分析器精确盘点 499 文件 / 191 处，分九批改完复扫到 0，独立编译 0 错，再三人只读复审等价；注意含数组解引用的条件要先守卫再求值，否则会丢短路。 |

> 其它可速答（详见详尽版）：CD 用“服务器截止时间−服务器时间”转秒、本地不缩放时钟倒计时，不做 RTT 补偿；role_skill 数据错用备份+SQL 修而非改 TryCast 兜底（需重登才生效）；连招表 GetComboReplaceSkillID 返回的是效果表 ID；气墙 CheckWall 本项目只读未移植；空连接路径只能在 Editor 跑表现，不能证明在线提交成功。

## 八、未完成边界

> 主动说边界不是减分，而是证明你知道做到哪了。下面这些没做完的，被问到要主动认，不要等被拆穿。

| 模块 | 现状 |
| --- | --- |
| 目标命中 / 伤害 / Buff / 刷怪 | 未做，客户端只有辅助选敌 |
| 移动服务器物理权威 / AOI | 未做，服务器不校验速度路径穿墙、无速度字段 |
| 性能 / FPS | 主城关了 54 个实时点光，但无 Profiler 前后对比，不报 FPS、不报收益 |
| 联机验证 | 多数案例停在独立编译 / 原生隔离 / 真实包读取，未真人联机与安装包 |
| role_skill 数据修复 | SQL 修复后未真人联机验证，需重登确认 |
| 布尔重构 | Roslyn 静态复扫 499 文件 / 191 处到 0，未做 Unity 运行时冒烟 |
| Shader / IPC / Burst | 首次内部起因未证明 |
| AOI / 大规模联机 | 未做，当前只同图 100 米 `IsNearbyRole` 过滤，未压测在线人数 |
| 抖动缓冲 / RTT 回滚 | 远端影子追赶没有这些完整系统，是后续优化方向 |

> ⚠️ **验证分层：** 源码专项 → 独立编译 → 原生隔离 → 真实包 / 回环 → 正式联机。面试时先说清当前结论做到哪一层，不把隔离验证说成正式验收。

**一句话收尾：** 这个项目我最有把握讲的是“客户端怎么跟手、服务端怎么权威、两边怎么用 UUID 和残差对齐”；最该主动认的是“伤害和物理权威还没做”。主动说边界，比被问出来再补要稳。

### 三条红线（脱口前自检）

1. 不说“帧同步”——这是位置状态上报 + 影子追赶。
2. 不报 FPS / 不报性能收益——没有 Profiler 前后对比。
3. 不说“目标伤害做完了”——只做了准入、消耗、表现和客户端辅助选敌。
