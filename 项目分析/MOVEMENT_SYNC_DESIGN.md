# 玩家移动同步设计方案

## 1. 设计目标

本方案用于当前项目的主城和普通场景移动同步，目标是让玩家 A 移动时，附近玩家 B 能看到平滑移动，同时避免服务器运行完整 Unity 场景物理。

本阶段明确不做以下内容：

- 不让 GameServer 读取 Unity Scene、Prefab 或 FBX。
- 不让 GameServer 每 50ms 对所有玩家运行完整物理模拟。
- 不要求所有客户端使用相同逻辑帧进行确定性模拟。
- 不把移动同步设计成帧同步。
- 不把普通移动直接用于严格的 PvP 命中和攻击距离结算。

本阶段采用“客户端位置快照 + 服务器轻量校验 + AOI 广播”。

## 2. 核心流程

```text
客户端本地立即移动
    -> 移动期间按间隔上传当前位置快照
    -> GameServer 逻辑线程做基础距离校验
    -> 服务器保存最新合法位置
    -> 服务器广播给附近玩家
    -> 其他客户端对位置快照做插值显示
```

网络线程只负责把协议复制为 `GameCommand` 并入队，角色位置只能在 GameServer 逻辑线程中更新。所谓“立即广播”是指逻辑线程消费成功后立即发送，不是在网络回调线程直接修改角色。

## 3. 客户端上行数据

概念协议名：`RoleMoveSnapshotReq`，表示客户端上报当前移动表现快照。

建议字段：

| 字段 | 说明 |
| --- | --- |
| `MoveSeq` | 当前角色递增的移动序号，用于丢弃旧包和合并过期包。不是公共逻辑帧号。 |
| `Position` | 客户端当前坐标，包含 X、Y、Z，单位为项目世界单位；如果项目约定 1 Unity 单位等于 1 米，则可按米理解。 |
| `Velocity` | 当前移动速度向量，单位为项目世界单位/秒，用于其他客户端插值和短时外推。 |
| `RotationY` | 角色水平朝向，单位为角度。 |
| `MoveState` | `Idle`、`Walk`、`Run`、`Jump` 等表现状态。 |
| `MoveMode` | 普通移动、骑乘、游泳等移动模式。 |
| `ClientTime` | 客户端采样时间，单位为毫秒，仅用于排查延迟和辅助判断，不作为服务器权威时间。 |
| `SyncReason` | 开始移动、持续移动、停止移动、方向变化、技能开始、技能结束、场景进入等原因。 |
| `SkillId` | 技能开始或结束时填写的技能配置编号，普通移动填写零。 |

`RoleId` 不由客户端决定，GameServer 从 Gate 会话和在线角色中取得。`SceneId` 也不直接信任客户端提交的值，以服务器当前场景为准。

## 4. 上行同步时机

### 4.1 开始移动

玩家从静止变为移动时立即发送一次。

### 4.2 持续移动

移动期间每 `300ms` 发送一次位置快照。该值作为默认配置，可按移动模式调整，但不允许由客户端动态修改。

这个快照用于让服务器和附近玩家知道角色仍在移动，不代表服务器每次都重新模拟完整物理。

### 4.3 立即同步事件

以下事件不等待定时器：

- 停止移动。
- 方向明显变化。
- 行走、跑步、冲刺或骑乘模式变化。
- 跳跃开始和落地。
- 技能开始。
- 技能结束。
- 场景切换。
- 服务器位置校正后客户端重新落位。

静止状态不发送移动心跳。

## 5. 服务器处理

GameServer 收到 `RoleMoveSnapshotReq` 后，流程如下：

```text
网络线程收到协议
    -> GameCommandDispatcher 入队
    -> 逻辑线程消费命令
    -> 找到 OnlineRole
    -> 检查 MoveSeq 是否过期
    -> 检查时间间隔和移动距离
    -> 接受或校正位置
    -> 保存角色移动状态
    -> 按 AOI 广播给附近客户端
```

服务器保存的最小运行时数据：

- 上一次合法位置。
- 上一次逻辑线程接受该角色移动状态的服务器时间，单位为毫秒。
- 上一次合法移动序号。
- 当前移动状态和移动模式。
- 当前朝向。

## 6. 服务器轻量校验

当前阶段不做 NavMesh、坡度、高度图和完整静态碰撞检测，只做明显异常检查。

服务器使用逻辑线程的单调服务器时间，根据两次接受状态之间的时间计算允许距离。不能直接使用网络线程收到数据包的时间，因为 TCP 合包、线程调度和消息队列积压会造成误判。

允许距离计算为：

```text
允许距离 = 配置最大速度 × 服务器时间间隔 × 容差系数
```

如果客户端上报的两次位置距离明显超过允许距离，服务器执行以下一种处理：

1. 记录异常并暂时接受，适合网络抖动较大的普通场景。
2. 使用服务器保存的上一次位置覆盖客户端位置。
3. 发送位置校正通知。

当前项目建议先采用“记录异常 + 超过明显阈值才校正”，避免因为一次延迟就把正常玩家拉回。

服务器不判断玩家具体站在哪个坡面，客户端负责使用 Unity 场景计算坡面表现。后续如果加入严格 PvP，再单独增加战斗区域的服务器场景校验。

## 7. 服务器下行广播

概念协议名：`RoleMoveSnapshotNotify`，表示服务器确认后的角色移动快照。

建议字段：

| 字段 | 说明 |
| --- | --- |
| `RoleId` | 角色持久化身份。 |
| `EntityUid` | 场景实体运行时身份，用于客户端找到对应 `RoleEntity`。 |
| `Position` | 服务器当前接受的角色位置，单位为项目世界单位。 |
| `Velocity` | 服务器当前接受的速度向量，单位为项目世界单位/秒。 |
| `RotationY` | 服务器当前接受的角色朝向，单位为角度。 |
| `MoveState` | 当前移动表现状态。 |
| `MoveMode` | 当前移动模式。 |
| `ServerTime` | 服务器处理该快照的时间。 |
| `MovementVersion` | 服务器移动状态版本，用于丢弃旧快照。 |
| `SyncReason` | 本次同步的原因。 |
| `SkillId` | 技能开始或结束时对应的技能编号。 |
| `Accepted` | 服务器是否接受本次客户端快照；拒绝时客户端必须使用服务器位置。 |
| `CorrectionReason` | 位置被校正时的原因，正常接受时为空。 |

服务器只向同一场景、同一线路、AOI 范围内的客户端发送，不全服广播。

如果服务器拒绝客户端位置，客户端原始非法位置不得广播给 AOI 玩家。角色 A 收到 `Accepted=false` 和服务器权威校正位置；角色 B、C 只收到校正后的 `Accepted=true` 快照，避免附近玩家短暂看到非法位置。

## 8. 技能开始和结束同步

### 技能开始

客户端发送技能开始快照，至少包含：

- 当前角色位置。
- 当前角色朝向。
- 技能编号。
- `MoveState` 或技能表现状态。
- `MoveSeq`。

服务器接受后，一份权威结果同时返回给技能发起者，并广播给附近玩家，使发起者和其他客户端从同一位置播放技能。

### 技能结束

技能结束时发送最终位置和朝向：

- 没有位移的技能，也发送一次带当前位置的技能状态快照，保证技能起点和移动状态一致；不需要单独同步位置时，可以复用普通移动快照字段。
- 有位移、冲刺、突进或击退的技能，必须同步最终位置。

技能结束位置只作为普通移动同步使用。严格的技能命中、攻击距离和伤害结算不能仅依赖客户端位置。

## 9. 客户端接收和表现

### 本地玩家

本地玩家先根据输入立即移动，收到服务器快照后只做误差修正：

- 误差小：平滑修正。
- 误差明显：移动到服务器位置。
- 技能位移、场景切换和强制拉回：直接采用服务器位置。

### 其他玩家

其他玩家不执行对方的输入，只保存最近几次服务器快照并插值显示。

如果超过约 `300~500ms` 没有新快照：

- 暂停继续外推。
- 保持最后位置或进入等待状态。
- 等待下一次快照或请求重新同步。

不能根据最后一次速度无限向前移动。

## 10. TCP 队列处理

移动快照属于可合并的普通消息。同一个角色有多条未消费普通快照时，只在不越过待处理关键事件的前提下保留 `MoveSeq` 最大且仍有效的一条。

以下消息不能被普通移动快照覆盖：

- 停止移动。
- 技能开始和结束。
- 场景切换。
- 瞬移。
- 击退和拉回。
- 死亡导致的移动终止。

客户端上行的所有移动事件先按 `MoveSeq` 排序；服务器接受一条状态后再递增生成 `MovementVersion`。如果 `MoveSeq=5` 的停止或技能开始事件尚未消费，不能先处理 `MoveSeq=6` 的普通移动快照；普通快照只能在下一个关键事件之前合并。关键事件不能被普通快照覆盖。客户端下行只按 `MovementVersion` 丢弃旧结果，`MovementVersion` 不是公共逻辑帧号。

## 11. 这不是帧同步

本方案没有以下帧同步特征：

- 没有公共 `FrameId`。
- 不等待所有玩家提交同一帧输入。
- 不把玩家 A 的输入广播给玩家 B。
- 玩家 B 不执行玩家 A 的输入。
- 客户端不需要和服务器运行相同的确定性物理模拟。

服务器的 `50ms` 逻辑帧只用于消费命令和更新业务，不是网络同步帧。

## 12. 术语说明

### 位置快照

某个时间点角色的位置、朝向和移动状态。它不是客户端永久正确的证明，而是一次同步数据。

### AOI

Area of Interest 的缩写，表示玩家当前需要看到的附近区域。服务器只把角色移动发送给 AOI 内的玩家。

### 插值

客户端在两个服务器位置之间平滑移动，默认保留约一个 `300ms` 同步间隔的插值缓存，避免收到一个位置就瞬移。

### 外推

客户端根据最后一次位置和速度，短时间预测角色下一步位置。外推只能持续很短时间，不能无限进行；超过 `300~500ms` 未收到新快照时应停止外推。

### MoveSeq

客户端移动序号，用于判断同一角色上行移动数据的新旧顺序，建议使用无符号递增整数。它不是服务器逻辑帧号，也不要求所有玩家保持一致。

### MovementVersion

服务器每接受一条移动状态就递增的角色移动版本，建议使用无符号递增整数，用于保证停止、技能位移、位置校正等消息不会被旧移动覆盖。它不是服务器逻辑帧号。

### 轻量校验

只检查时间、距离、速度等明显异常，不检查完整地形、坡度和 Unity 物理。

### 位置校正

服务器认为客户端位置明显异常时，发送服务器接受的位置，客户端回到该位置继续移动。

## 13. 推荐实现顺序

1. 客户端移动开始、持续、停止快照。
2. GameServer 保存角色最新位置。
3. GameServer 基础距离异常检查。
4. AOI 范围内广播移动快照。
5. 客户端其他玩家插值。
6. 技能开始和结束位置同步。
7. 位置校正和断线重连完整快照。

本阶段不实现服务器场景物理和 NavMesh 校验。

## 14. 方案审核结果

本方案经过独立架构审核两轮后通过。审核确认：方案采用客户端位置快照和服务器轻量校验，不使用公共帧号、不等待所有客户端输入、不要求客户端确定性重演，因此不属于帧同步；移动频率、技能起止同步、TCP 队列合并、AOI 广播和术语定义满足当前项目的主城与普通场景需求。

## 15. 跳跃同步设计

跳跃属于移动状态变化，沿用位置快照同步，不单独引入服务器物理模拟。

### 15.1 跳跃开始

客户端按下跳跃后立即发送一条快照：

- `MoveSeq`
- `Position`
- `RotationY`
- `MoveState=Jump`
- `SyncReason=JumpStart`
- `JumpId`
- `JumpVelocityY` 或 `JumpDuration`

客户端本地立即播放跳跃表现，不等待服务器回包。

### 15.2 空中移动

普通跳跃时间较短时，只需要发送起跳和落地两次快照。如果跳跃持续时间超过 `300ms`，空中按普通移动间隔发送位置快照。

空中快照必须继续携带：

- 当前三维位置。
- 当前水平速度。
- 当前朝向。
- `MoveState=Jump`。
- `JumpId`。

### 15.3 落地

客户端检测到落地后立即发送：

- 最终位置。
- 最终朝向。
- `MoveState=Idle` 或 `MoveState=Run`。
- `SyncReason=JumpEnd`。
- 对应的 `JumpId`。

没有服务器场景数据时，服务器不能判断客户端是否真的接触地面，因此落地位置由客户端上报，服务器只进行基础异常检查。

### 15.4 GameServer 校验

服务器不计算完整抛物线，只检查：

- 跳跃是否处于冷却或禁止状态。
- `JumpId` 是否重复或倒退。
- 起跳到落地的时间是否明显过短或过长。
- 垂直位移是否超过配置上限。
- 水平位移是否超过最大速度允许范围。
- 是否在技能、眩晕、死亡等状态下禁止跳跃。

如果检查通过，服务器保存跳跃状态并广播给 AOI；如果明显异常，服务器向发起者发送上一次合法位置或位置校正，不把非法位置广播给其他玩家。

### 15.5 其他客户端表现

其他玩家收到 `JumpStart` 后开始播放跳跃，收到空中快照时修正位置，收到 `JumpEnd` 后切换到落地后的移动状态。

`JumpId` 用于防止旧的落地包覆盖新的跳跃状态。客户端不能在没有收到新的跳跃开始时重复处理落地包。

### 15.6 断线和丢包

- 起跳和落地快照必须进入可靠的移动事件顺序。
- 服务器超过一次最大跳跃时长仍未收到落地包时，将角色标记为跳跃超时。
- 跳跃超时只做状态结束和位置快照请求，不直接运行场景物理寻找落点。
- 重连或 AOI 新加入时发送当前三维位置和当前跳跃状态；如果角色仍在空中，还要带 `JumpId` 和剩余跳跃时间。
