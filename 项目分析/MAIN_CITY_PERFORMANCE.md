# 主城灯光与性能调查

## 本轮范围与结果

依据用户要求，在 `LYF_MMO/Assets/GM_Game/Scenes/Scene_MainCity.unity` 的 `MainCity_Geometry` 预制体实例中增加 54 个 `Light.m_Enabled=0` 覆盖。只关闭内部实时点光组件，不关闭承载水晶、火焰、装饰模型的父节点，不改变共享预制体、后处理、相机、全局画质或业务更新代码。

原生 Unity 2023.2.20f1c1 预览场景核验：场景含 60 个 Light 组件，其中修改前活动且启用 55 个：54 个实时点光、1 个烘焙方向光；实时点光中 13 个启用软阴影。修改后活动且启用只剩 1 个烘焙方向光，实时灯 0 个、活动阴影灯 0 个。原有外部 `Lights` 父节点已被用户禁用，本轮保持，未再次开启主光。共享 `MainCity_Geometry.prefab` 仍保留原 55 个启用灯组件，其他场景不受本轮覆盖影响。

这解决了“关掉外层 Lights 仍留下内部点光”的具体问题。烘焙方向光不新增实时阴影成本；环境光、天空盒与原有烘焙配置保持。

## 已确认的负载事实

| 证据 | 观察 | 解释与边界 |
|---|---|---|
| 原生主城预览场景，修改前 | 54 个活动实时点光，13 个软阴影点光 | 点光和点光阴影是实际启用的渲染负载；关闭后此项负载已移除。不能仅凭数量推断游戏帧耗时占比。 |
| 原生主城预览场景 | 2020 个活动且启用 Renderer，其中 1983 个对象为静态；活动 MeshFilter 网格合计 8,345,721 个三角形 | 是整个场景活动网格总量，包含镜头外模型，不能宣称每帧提交或可见三角形数，也不能直接等同 DrawCall。高几何规模仍是持续低帧率的重要待测项。 |
| 现场历史 Editor.log 的正式进城段 | 主城加载总耗时 9036.005 毫秒，反序列化 2044.068、整合 3671.794、资源整合 281.149、线程等待 3038.994 毫秒 | 证明进城时确有明显加载卡顿；属于一次场景加载成本，不是稳态每帧耗时。证据摘录保存于本轮临时目录。 |
| 原生质量读取及项目配置 | 当前 Ultra，vSync=1，Builtin 管线；质量配置允许 4 个逐像素光、阴影距离 150、4 级联及高 LOD 偏置 | 是实际高画质配置，但垂直同步本身不证明存在故障。本轮不为降低帧率数字更改全局画质。 |
| 主城相机序列化及原生读取 | 活动 Main Camera 远裁剪面 5000、CullingMask=-1；主城无烘焙遮挡数据引用 | 镜头可纳入很远的模型，未获得烘焙遮挡收益；应通过可见模型数量与渲染采样确认影响，不擅自缩短视距。 |
| 主城后处理配置 | 活动 PostProcessLayer，FXAA；全局配置启用 AutoExposure、ColorGrading、AmbientOcclusion（强度 0.4）；Bloom 值为禁用且强度 0 | AO 和后处理是具体待测 GPU 负载。不能把配置中关闭的反射、景深、Bloom 当成已运行热点。 |
| 小地图与角色更新源码 | 小地图使用图片坐标位移；预置角色预览相机所在角色父节点 inactive；MainCityMgr 每帧补订阅/补创建通常快速返回 | 没有证据支持“小地图每帧再渲染整城”或“每帧重复创建角色”。本轮没有据此修改业务代码。 |

## 验证方式与画面边界

通过 Unity MCP 在当前编辑器调用 `OpenPreviewScene`，每次在 `finally` 中 `ClosePreviewScene`；用户活动场景一直是 `Assets/Boot/Scene_Boot.unity`，其 dirty 状态前后均为 false。没有启动或结束游戏，没有挂测试组件，没有保存用户当前场景。

`before.png` 与 `lights-off.png` 来自主城预览场景的活动 `Main Camera`（世界位置约 59.15、21.91、80.64），临时 1280×720 RenderTexture；后者只在预览对象上关闭实时灯后渲染。该视角的角色和地面可辨，两图几乎一致，说明这个室外视角没有明显点光贡献；不能据此宣称室内和全城外观完全不变，也不能将预览图当正式登录后的游戏运行验收。

正式场景末稿原生重载确认 54 个覆盖全部生效；共享预制体仍是原 55 个灯启用。修改只插入 9336 字节覆盖，移除此插入段后与现稿 before 字节完全相同，全部既有用户修改保持。场景 before SHA256：`2f2e8c14aaaa57cabd1f34f3a2b6ecf14830a6e136d80b13234385dd4ab2466e`；末稿 SHA256：`48df3d37b4891b496981043807f1b71dc98c403f2a3692adeec713180a1895b1`。

首次图片预览清理临时 RenderTexture 时，先销毁纹理、后关闭仍引用纹理的预览相机，产生一条 `Releasing render texture that is set as Camera.targetTexture!` 诊断。已将临时验证清理顺序改为先 `camera.targetTexture=null`，重新渲染末稿并保存 `final-lights-off.png`，执行成功。该诊断属于临时预览验证，不是业务编译或正式主城运行故障，没有为此修改业务代码。

## 尚未完成的实测与下一步

当前编辑器处于非 Play 的启动场景，未采集真实进入主城后的 CPU/GPU Profiler 帧，因此不报告 FPS 提升数值，不把灯光或模型负载认定为唯一根因。下一步通过原正式登录入口进入主城，在相同镜头、分辨率和质量下比较关灯前后 CPU/GPU 帧时间、Batches、Triangles 和 Shadow/Cull/PostProcessing；区分进城加载尖峰与停留主城后的持续负载。再根据实际排名只处理热点，避免先扩大场景优化范围。
