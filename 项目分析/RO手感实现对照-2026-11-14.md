## 一、总纲：表现轨与结算轨彻底切开

RO 手感的钥匙不是低延迟传输，而是一句职责切分：**动作表现全部本地先演，伤害结算全部服务器权威后至**。

- 客户端点技能 → 走到施法范围 → 发 `RpcC2G_SingingRequest`（`SkillId` + 目标 + `castPoint` + `skillUuid`）→ 发送成功后 `MGamelibNetEventListener.FireSkill` 立即本地播放；`MSkill.Fire` 中不存在「等回包才 Fire/Start」的门禁。
- 服务器 `SkillStart` 回来只做 UUID 匹配确认、不重播；`SkillEnd` 触发 `Cease`；伤害/飘字/命中特效另走 `kNetEventSkillResultTarget`、`kNetEventDamageResult`、`kNetEventJumpWord`。
- 预表现 2 秒内未确认则自动结束并 `MSkillCore.Reload()` 撤销本地预测 CD；确认后的旧实例有 10 秒宽限保留尾音、粒子与长音。
- **有预表现，无状态回滚**：服务器不把玩家拉回施法前状态，只有 `MPlayer.CorrectSyncPos` 做简单位置校正。宁可不校正动作，也不让玩家看到角色被拽回去。

依据：`客户端架构分析/05_战斗与技能系统.md` §3.3、§7.1–7.3；`项目分析/RO_SKILL_SEND_MODULE_FLOW.md`；`项目分析/RO_SKILL_CD_LIFETIME.md`。

## 三、L2 输入、移动与相机

### 单槽输入缓存（预输入）

`UISystem/Ctrl/Skill/MWaitingDataMgr.cs`：

- 类注释明确「管理技能释放、导航、便捷寻路数据状态类，在同一时间，只允许出现一个状态」。
- `Update()` 每帧检查：`player.IsWaitingForServer`、`!player.Machine.CanSkill()`、导航中且无保存点 → 先返回，不丢弃缓存；`MVirtualTab.singleton.IsMoving` → `ClearAll()` + `ClearWaitingCommonAttack()` 主动放弃。
- 条件满足后 `DoAction()` 执行 `_waitTodo`，成功即 `ClearAll()`；同时维护普攻等待 `_waitCommonSkillCore` / 自动攻击目标。

这就是「按早了能被记住」的 RO 版本：**一个槽、按帧重试、一移动就放弃**，而不是多键队列。

### 位移：不用 Unity RootMotion

- 全工程 C# 侧搜不到 `OnAnimatorMove / applyRootMotion / deltaPosition` 的正式技能位移链。
- 位移由 `MSkillData` 的 `ChargeList/ECharge` 配置：`CurveX/Z`、`DistanceX/Z`、`At/End` 秒；`MArtSkill.FireEvents()` 到点派 `MEvent_Displacement`，`MDisplacementComponent` 每帧按归一化曲线积分，并做踢墙、贴地高度、空气墙检测后赋 `Entity.Position`。
- 设计理由（`客户端架构分析/07_技能特效与技能脚本实现.md` §8.6）：服务器权威防作弊；碰撞/导航/贴地可控；网络同步只需「技能 ID + 已进行时间」；`MEvent_DisplacementStop` 可随时打断、`_timeScale` 可调速；动画与位移解耦、同动画可配不同距离。

### 相机与状态

- `Camera/Components/Function/MCameraShakeComponent.cs`：注册 `MEventType.MEvent_CameraShake`，带随机/交替方向、位置振幅、FOV 增量与曲线包络，逐段 `Lerp` 抖动；`MPlayerSetting.IsCameraShakeEnable` 可关。技能侧由 `UseCameraShake / ShakeOnlyCri / CameraShakeData / CameraShakeIndex` 触发。
- 另有 `MCameraFixedAngleComponent`、`MCameraOffSetComponent`、`MCameraAdaptiveComponent` 负责战斗锁定与跟随，`MCameraLayerCullComponent`、`MCameraOcpBoxComponent` 负责遮挡；配表 `CameraConfigTable`、`CameraAngleTable`、`CameraFxViewRadius`。
- 受击侧 `Components/Common/MBeHitComponent.cs` 按 `resultData.BeHitCameraFx` 调 `MFxMgr.CreateCameraFx`。
- 两层状态机：原生 `ROGameLibs.StateMachineComponent` 管权威逻辑状态，客户端 `MStateMachine` + `MActionComponent` 管动作表现；`StateDefine` 15 态配 `StateExclusionTable` 互斥矩阵，动画播放统一延迟到 `LateUpdate`。详见 `项目分析/RO_STATE_MACHINE_RUNTIME_ANALYSIS.md`。

## 四、L3 战斗与打击感

### 时间轴脚本，不是 Animation Event

- 技能是一份 protobuf `MSkillData` 时间轴：特效、音效、震动、预警、位移、动画覆盖每个事件都带 `At`（触发秒）。`MArtSkill.Start()` 一次性 `FireEvents()`，按 `At * _timeScale` 注册 `MTimer` 定时器，到点由 `InnerProcessTimer` 直接派发；`MArtSkill.Update` 只处理朝向旋转，不每帧扫描时间轴。
- 帧换算：`帧数 = At(秒) × 帧率 ÷ 攻速缩放`。攻速改变压缩的是 `At` 与状态时间，命中帧仍被时间轴锚定，不是整段动画等比快放。
- 上百技能共用 Animator 里同一个 `Skill` 槽位，运行时用 `MAnimator.OverrideAnim("Skill", 路径)` 换 `AnimatorOverrideController` 中的 Clip，再 `Play/CrossFade`；多段挥刀由 `AnimList` 各自 `BeginTime` 到点切换。

依据：`项目分析/RO_SKILL_TIMELINE_RESPONSIBILITY.md`、`客户端架构分析/07_技能特效与技能脚本实现.md` §三、§五。

### 三个独立时间字段与接段点

RO 剑士三段普攻配置（`config/Assets/Resources/SkillData/Player_Swordman/Player_Swordman_GongJi_*_0_1.txt` 第 18–20 行）：`Time=0.9s`、`AnimationLength=0.6s`、`SkillStateTime=0.7s`。

- `MArtSkill.IsEnd()` 按 `SkillStateTime` 判定退出技能状态，源码注释明确「自动战斗也不再等待完整动画」；`MSkillComponent` 在 `IsEnd()` 后 `Finish()`。
- 服务端 `art_skill.cpp` 用 `skillstatetime()` 注册 `StateTimeEnd`，`time()` 另注册 `SkillTimeEnd`；`MCombineSkill` 在当前子技能 `IsEnd()` 后 `SkillStateEnd()` 起下一段。
- `IsEnd()`（动作状态到期）与 `MSkill.Update()` 返回 false（生命周期终止）是两件事；自然结束要求 `HasServerEnded && IsPresentationFinished`，不能只看动画或状态时长。
- 本项目对照：MJS `Anim_MJS_Atk01/02/03` 约 2.167/1.967/2.5 秒，另配 `SkillStateTimeMs=700` 作为节奏参数，属于「状态时间明显短于动画」的反向用例，超过 700 ms 的动画尾部会被下一段或 Idle 过渡截断。

依据：`项目分析/RO_Q_COMBO_TEMPO_REFERENCE.md`、`项目分析/RO_NORMAL_ATTACK_USING_TIMES_DESIGN.md`、`项目分析/RO_SKILL_CD_LIFETIME.md`、`项目分析/2026-11-03-RO技能主动打断与组合接段分析.md`。

### 打断、命中与 CD

- 打断不是无条件取消：处于技能状态时检查**新技能**的 `InteruptSkill` 是否包含当前技能 ID，并要过 `CanActiveInterrupt()`；`rpcc2g_stopstate` 与 Buff 停止状态都受同一门禁约束。`Freeze()` 调 `KillTimeAll()` 清未到期事件、停止弹体；**已结算 HP 不回退**。组合技子技能非自然结束会终止整个组合。
- 命中类表现不走客户端时间轴：`FireServerEvents` 按服务器结果的 `NoResultIndexList` 跳过未生效段，只为生效段注册命中特效，避免「没打中却播命中」。
- CD 分两套表（单技能 `SkillCDDic`、公共组 `SkillCDGroupDic`），每帧倒序递减、到零归池；`Performance()` 写本地预测 CD、`Reload()` 撤销、`SetTimer(cd, groupCd)` 接权威同步，RO 用 `DelaySeconds * 2` 做网络估算补偿（本项目无同样契约，不可直接移植）。
- 反馈清单：曲线包络震屏 + FOV 抖动、`kNetEventJumpWord` → `DotHudTable` 飘字（伤害/治疗/暴击/Miss/属性增减）、FMOD `Action.bank` 音效按 `At` 派发、受击动画、地面预警圈。

依据：`项目分析/2026-11-03-RO技能主动打断与组合接段分析.md`、`项目分析/RO_SKILL_CD_LIFETIME.md`、`客户端架构分析/05_战斗与技能系统.md` §6.3–6.5、`项目分析/RO技能命中判定分析-2026-10-31.html`。

## 五、L4 认知与一致性

- 所有技能共用同一 `Skill` 槽位、同一份 `MSkillData` 时间轴格式、同一套状态互斥矩阵与打断许可规则；规则只有一套，肌肉记忆才能建立。
- 普攻三段轮换 `UsingTimes`：客户端距 `fire_time` 超 10 秒置零否则递增取模；服务端 `SkillComboTime` 默认 6 秒窗口。发包后本地按索引预表现，服务器 `SkillStartInfo` 广播权威 `using_times`，本人 UUID 匹配只确认不重播，远端按权威索引播放。两端窗口差异按各自源码保留，不擅自统一。
- 反馈可读性：点击射线 + 选择优先级、瞄准键候选、脚下 `MTargetFxComponent` 选择特效、目标有效性/距离/可见性维护（`项目分析/RO_TARGET_SELECTION_FLOW.md`）。
- 已结算伤害保留、未到期事件清除、组合停止不再起下一段——这些规则在所有技能上一致，玩家才能预判「打断了会损失什么」。

## 六、RO 没做什么（同等重要）

本轮检索范围内**未找到**以下内容，不等于对其余模块或版本的绝对否定：

- Unity 原生 RootMotion（明确不使用，见 §三）。
- 顿帧 / hitstop 类时间缩放打击反馈；打击感主要靠时间轴精度 + 震屏 + 飘字 + 音效 + 受击动画。
- 完整客户端预测 + 服务器和解/状态回滚；只有预表现、超时撤回与简单位置校正。
- KCP/UDP 接入业务主流程的实例化证据；主游戏路径为 TCP。
- 面向手感的帧时间抖动治理；只有 FPS 观测统计。
- 服务器移动速度/碰撞/导航权威结算；服务器只保存并广播客户端终点。
- 与本项目独立滑行键、三段跳完全对应的无条件技能取消入口（2026-11-03 调查结论）。

## 七、代价与已知缺口

1. 命中特效与飘字等服务器确认，反馈天然背一个 RTT；动作先演、伤害后至是 RO 的核心取舍。
2. `result.GetResult() > 0` 才下发受击事件；被闪避时客户端「打过去没反应」，容易被玩家误判为伤害丢失（`项目分析/RO技能命中判定分析-2026-10-31.html`）。
3. 预表现 2 秒未确认会结束表现并撤销预测 CD；弱网下会出现「放了但白放」。
4. 状态时间与动画长度分离，动画尾部可能被下一段或 Idle 过渡截断，需人工目检挥击关键姿态是否完整。
5. 客户端不计算伤害、不信任客户端索引；一切数值由服务器下发。

## 八、与本项目对照（现状提示）

- 已分别对照移植：本地预表现与 UUID 确认、`SkillStateTimeMs`、三段普攻轮换、移动 0.1 秒节流上报与远端追赶、动画根运动/位移曲线接入、目标选择、伤害跳字资源、技能编辑器中的镜头与音效轨道。
- 仍有差距：`项目分析/RO_SKILL_SEND_MODULE_FLOW.md` 明确本项目 `SetWaitSkill` 为即时交接、**不保存等待队列**，即 RO 的单槽输入缓存未接入；`项目分析/2026-11-03-RO技能主动打断与组合接段分析.md` 指出服务端尚未实现 `ResultList` 逐段命中结算与「已命中保留、未到期取消」。这两处是最可能影响当前手感的地方。
- 本项目已有动画根运动（`SkillRootMotionCollector` 取 `Animator.deltaPosition`），与 RO 的曲线位移是两套不同方案，对照时注意勿混为一谈（`项目分析/SKILL_ROOT_MOTION_REMOTE_SYNC.md`、`项目分析/RO_SKILL_TIMELINE_RESPONSIBILITY.md`）。
