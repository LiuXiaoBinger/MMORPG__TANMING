# HFS模拟热更与启动进度停留

日期：2026-10-12。用户明确保留联网热更，以本机HFS2.4.0 RC7模拟资源服务器，地址为`http://192.168.9.1:8080/`，不切换离线模式。

## 实际失败阶段

最新Player日志显示资源初始化成功，随后出现Curl42及`UpdateManifest Error::Package version is null or empty.`，没有开始资源下载。启动场景的初始TMP文字固定为“下载进度【50%】”，因此截图上的百分比不代表真实传输状态。

Load在版本查询完成后错误地检查了初始化operation的状态和错误；版本请求失败仍向清单操作传入空版本。真实YooAsset1.5.7版本查询默认60秒无新增数据超时，使这个错误的占位提示持续较久。

## HFS现场核对

HFS进程位于`hfs/hfs.exe`，用户截图显示端口8080及bundle列表。初查未见8080监听，随后复查已监听IPv4和IPv6；在监听出现后，按配置IP以及127.0.0.1访问版本文件均5秒零响应，访问根目录HEAD亦4秒零响应。TCP连接可建立，当前不能据此断言服务器正常提供文件；不把问题直接归咎于文件不存在或防火墙。

本轮未关闭或重启HFS、替换其文件列表、清客户端缓存或发布资源。建议在浏览器验证`http://192.168.9.1:8080/PackageManifest_DefaultPackage.version`能立即返回版本号；当前对应产物版本为`2026-10-12-1039`，以实际发布产物为准。

HFS虚拟文件系统根应提供同一版本目录下的`.version`、对应版本`.hash`和`.bytes`清单及bundle，而不只是截图中可见的bundle。正式资源产物位置`LYF_MMO/Bundles/StandaloneWindows64/DefaultPackage/2026-10-12-1039`。恢复HFS请求响应后验证版本、清单和资源能连续获取。

## 客户端最小修复范围

`Assets/Boot/Load.cs`修版本状态判断，联网空版本停止，实际初始化/查询/清单/下载/代码/登录阶段提示，已失败步骤明确显示失败；版本和清单使用15秒无新增数据超时，大文件下载沿原参数。编辑器模拟模式合法空版本保持。`Scene_Boot.unity`只改初始占位文字，保用户Host模式、地址及布局。

保持真实下载字节百分比，不用假进度掩盖网络等待；无离线回退、额外重试管理、按钮或新框架。此前实际出现的热更DLL加载异常也在启动界面明确报告，不吞异常继续进入游戏。
