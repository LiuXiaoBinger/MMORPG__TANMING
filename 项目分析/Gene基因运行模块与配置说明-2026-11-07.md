# Gene 基因运行模块与配置说明

本项目统一使用 Gene／基因称呼增益和减益效果。本次范围为基因表、通用运行模块及实体生命周期接入；具体技能施加、战斗资源结算、客户端网络同步未接入。

## 配置入口与属性单位

源表：`Luaban/MiniTemplate/Datas/#Gene.xlsx`。运行数据：`LYF_Server/Network/LubanManage/Tb/tbgene.bytes`；类型由 Luban 生成到 `LYF_Server/Network/LubanManage/Codes/Gene.cs`。

工作簿按属性基因（57）、周期基因（5）、状态基因（5）、事件基因（3）、次数基因（3）、组合基因（7）分为六页，原 Sheet1 改名为属性基因。初版 69 条全部保留，新增 11 条事件、次数及跨类型组合示例，当前共 80 条。原 `buffTime` 字段改为 `GeneTime`，因此必须同时更新生成代码、二进制表及客户端 `Network.dll`，不能混用旧表和新解析器。

| 字段 | 配置规则 |
|---|---|
| Id / EffectDesc | 唯一编号及中文效果说明。 |
| Scenario | 0 全局，1 副本，2 PvP。全局配置在三类环境均可生效。 |
| ValueType / Value | 0 固定值，1 相对基础值百分数；10 表示 10%。负数表示削弱。Value 是每层数值。 |
| AttachGeneId0～4 | 所有类型都可填写五个关联编号，0 留空；支持跨页及嵌套组合，禁止直接或间接循环引用。 |
| IsStack / MaxStack | 同编号、同来源：IsStack=0 允许叠加，MaxStack=0 不限层；IsStack=1 只刷新。刷新恢复自身及关联触发节点的次数。不同来源独立。 |
| GeneTime | 持续秒数，0 常驻；运行时剩余时间为毫秒，-1 表示常驻。 |
| EffectType | 0 属性，1 持续伤害，2 持续治疗，3 持续回蓝，4 状态，5 组合，6 事件，7 次数。 |
| AttributeId | 属性效果使用 `GeneAttributeType` 编号；其他效果填 0。 |
| Interval | 周期毫秒数；持续伤害、治疗、回蓝必须大于 0。第一次触发在第一个完整周期结束时。 |
| State | 位标记：1 眩晕、2 定身、4 沉默、8 霸体，可相加。 |
| TriggerEvent | 1 命中、2 受击、3 施法、4 击败目标；次数基因填 0 响应任意有效事件，事件基因必须指定。 |
| TriggerCount | 次数基因允许触发的次数，必须大于 0；与叠加层数独立。 |

1～23 号与现有外功、内功属性保持一致。命中、暴击、格挡是面板点数，不是概率。暴击伤害 151 表示 151%，固定修正 +10 表示加 10 个百分点。23 号“气”保留为原表的基础属性，不代指法力或轻功气力；当前角色协议没有对应字段，调用方应自行提供基础值。

新增属性编号：24 移速（沿用基础速度单位）；25 承伤倍率百分数；26 受疗倍率百分数。后两者通常以 100 为基础值，目前只提供计算结果，不自动改写伤害、治疗或移动逻辑。

## 运行行为与调用入口

客户端 `MEntity.Gene.Runtime`，服务端 `GeneComponent.Runtime`。服务器通过 `GameServer.csproj` 链接客户端目录中的八份无 Unity 依赖的 Gene 源码，两端使用同一套算法，不另建管理器。

- `AddGene(geneId, sourceId, value)`：创建或叠加同来源实例并刷新寿命；数值覆盖只影响根自身，关联项使用各自表值。重复施加保留周期进度并补满次数。
- `RemoveGene(geneId, sourceId)`：只移除指定来源，同时移除其组合叶子。
- `CalculateAttribute(attribute, baseValue)`：基础值 ×（1 + 所有百分比修正之和 / 100）+ 所有固定修正之和，每项均计入层数。不写回基础值，避免到期时反算误差。
- `Update(deltaMilliseconds)`：返回本帧周期结果列表，跨越多个周期时补齐，但只结算真实存续时间。恰好在到期时刻完成的周期会触发。组件随后逐条发送 `Pulse` 事件。
- `GenePulse.ResolveAmount(maxHp, maxMp)`：固定点数直接取整；百分比伤害／治疗以目标生命上限为基数，回蓝以目标法力上限为基数，向零取整。宿主负责消费结果、应用承伤／受疗修正与资源上下限。
- `GetStates()` / `CanMove` / `CanCast`：提供控制判定。霸体屏蔽眩晕和定身，不屏蔽沉默；霸体期间已有控制仍计时，霸体结束后未到期的控制重新可见。
- `SetScenario(scenario)`：切换场景类型并移除不适用的父实例；组合叶子也按其场景过滤效果。
- `Trigger(GeneEventType)`：宿主显式传入事件，返回关联基因的实际施加／刷新数量。次数节点每次匹配扣一次，最后一次也执行效果；根次数耗尽后移除，组合内的次数耗尽只停止该节点。`None` 不触发，不按层数复制事件次数。调用示例为 `entity.Gene.Runtime.Trigger(GeneEventType.BeHit)`。
- `Clear()`：销毁或回收时清空。组件回收同时解绑周期订阅。

普通组合项与根实例共享层数、剩余时间和来源；子项的 GeneTime、IsStack、MaxStack 不单独执行。场景限制沿整条父子路径生效。事件／次数节点的关联项在触发前不生效；相邻事件和次数节点沿同一次事件判断并保留原次数，普通关联项在触发时作为新基因添加，使用自己的寿命和叠加规则。已生成基因独立存续，不因触发父项移除而回滚。

六个 Sheet 字段结构一致，仍导出到同一 `TbGene`。Luban 默认读取文件中的全部有效 Sheet，见 [Luban Excel 读取规则](https://www.datable.cn/docs/3.x/manual/excel)。

事件与次数参考 RO 的 `rogamelibs/entity/buff/buff_trigger_timing/buff_trigger_timing_hoster_event.cpp` 事件入口和 `buff.cpp` 的 `OnTrigger` 扣次职责；这里只提供强类型宿主调用入口，未接具体技能事件或客户端网络协议。

参考 RO 的 `rogamelibs/entity/component/buff_component.cpp`、`rogamelibs/entity/buff/buff.h` 中“实体组件持有实例、实例持有效果”、施加、刷新、周期推进与移除职责；只适配本项目需要的属性、周期、状态和五槽组合，未移植 RO 的专有技能、Lua 或网络体系。参考根目录为 `F:/UnityPro/ro/Ro_cs422nb`。

## 验证与使用边界

在项目根目录运行 `powershell -ExecutionPolicy Bypass -File Tests/Gene/run.ps1`。测试直接加载正式二进制表，并通过已编译的服务端实体工厂验证组件初始化、周期通知及销毁，所有产物写入 `_temp/gene-runtime-tests`。

当前通过 351 项断言：80 条真实配置、编号稳定、来源与叠加、刷新与周期边界、所有类型组合、嵌套组合、事件过滤、次数消耗／补满／耗尽、嵌套场景限制、循环拒绝及服务端实体生命周期。独立读取六页确认原 69 条数据值完整保留。服务端及客户端独立编译通过；编译保留现有项目警告。未执行 Unity 场景实机战斗、技能施加、联机同步或数值平衡验证。
